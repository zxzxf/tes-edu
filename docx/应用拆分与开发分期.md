### 1.3 为什么建议首个学科选「数学」（关键战略理由）

| 候选学科 | 命题方 | 内容可复用范围 |
|---|---|---|
| **数学**（建议） | 教育部考试院统一命题（新高考 I 卷） | **全部 11 个新高考 I 卷省份**：河北、江苏、浙江、安徽、福建、江西、山东、河南、湖北、湖南、广东 |
| 语文 / 英语 | 教育部统一命题（新高考 I 卷） | 同上，但英语教材版本差异大（河南用北师大版） |
| 物理 / 化学 / 生物 / 政 / 史 / 地 | **河南省自主命题** | **仅河南 1 省** |

**结论：先做数学。** 数学是新高考 I 卷下的全国统一命题科目，且新高考数学**不再分文理**（一张卷），一套内容可复用到 11 个省份——同样的内容投入，市场覆盖放大 11 倍。反之若先做选考科目（如物理），那是河南自主命题，内容只能河南用，复用率为 1。

### 1.4 选择「河南 · 高中」的理由与代价

**理由**：
- 河南是**高考生源大省、录取竞争最激烈省份之一**，提分刚需极强，家长付费意愿高。
- 河南 2026 年刚转新高考，**学生与老师对新高考考情最焦虑、最缺工具**，是切入窗口期。
- 高中生自主学习能力与移动端使用习惯成熟，最适配"学生端 App + 自适应路径"形态。
- 高中生具备抽象思维，能真正承载**苏格拉底引导式提问**（引导式教学在高中效果显著优于低龄段）。

**代价与注意事项**：
- 高中知识点更多、更难，图谱构建与内容标注成本高于初中。
- 题干更长、**解答题与压轴题占比高**，对 OCR 识别与 RAG 检索要求更高。
- ⚠️ **河南 2026 年首考新高考，河南本地"新高考真题"几乎为零**（详见第八节风险 R2）。

## 二、核心能力主张（差异化：图谱驱动，而非题库驱动）

依据市场对比，本系统真正的差异化不在"功能多"，而在**表示法**：

### 1. 知识点掌握度图谱（基于 Apache AGE / 图数据库）

- 把学科知识拆成**知识点节点 + 前置依赖边**，构成有向无环图（DAG）。
- 每个学生持有一份**掌握度向量**：每个知识点一个掌握度分值。
- 学生做题 → 更新相关知识点掌握度：
  - 答对 → 正向更新（含该题涉及的知识点及其祖先节点）
  - 答错 → 负向更新，并沿图谱**回溯前置薄弱点**
  - 长期未练 → 遗忘衰减（贴合艾宾浩斯曲线）
- **与市场的差异**：多数竞品是**题库驱动**（题 → 题推荐）；本系统是**图谱驱动**（题 → 知识点 → 学习路径）。

### 2. 自适应学习路径（基于最近发展区 ZPD）

- 基于掌握度图谱动态计算**最近发展区**：前置知识点已掌握、当前知识点未掌握的那个区间。
- 只推 ZPD 内的题：不推已掌握的（避免无效刷题）、不推远超当前能力的（避免挫败）。
- **难度自适应**：答对升难度、答错降难度。
- 错题闭环：定位薄弱知识点 → 推送针对性变式题 → 生成间隔重复复习计划。
- **高中适配重点**：须支持**解答题/多步题**的掌握度归属（一道题涉及多个知识点，需按步骤拆分归因）。

### 3. 苏格拉底引导式对话（Agent 的**默认**模式）

- **不直接给答案**，用提问引导学生自己得出解法。
- 这是市场头部（Khanmigo、小励、上清北 AI）的**共同核心教学理念**，是本系统必须对齐的教学底线。
- 交互节奏：反问 → 渐进提示（Hint 1 → Hint 2 → Hint 3）→ 学生仍卡住时才给完整讲解。
- **这条把 `/solve` 从"答案输出器"变成"导师"**，是本计划书 P2 的核心交付。
- **高中适配优势**：高中生能理解并配合引导式反问，是本系统选择高中学段的重要理由之一。

## 三、可开发应用清单（沿用）

### 1. 学生端 App（C 端，核心产品）
- **技术**：Android（Kotlin + Jetpack Compose），或 Flutter 跨端
- **面向**：**河南高中生**（首期）
- **功能（六大能力页）**：文本/语音输入、拍照识题、讲解展示（公式渲染）、触类旁通、知识图谱可视化、背诵卡/错题本
- **离线**：Room 本地缓存背诵卡与错题本

### 2. Web 管理后台（B 端，运营中枢）
- **技术**：Web（复用后端 API）
- **面向**：教研员、教师、家长、管理员（RBAC 四角色）
- **功能**：教研内容管理、学情看板、错题本、自动组卷、教师批改、家长周报、互动配置、多模态管理、合规审核

### 3. Agent 后端服务（AI 核心，被两端共用）
- **技术**：FastAPI（Python）
- **定位**：必须**独立开发部署**的服务，提供 `/solve`、`/solve_image` 等 API，内含 Orchestrator、RAG、LLM、OCR、图谱查询
- **价值**：学生 App 与 Web 后台都调它，是系统的"大脑"

### 4.（可选）微信小程序 / Flutter 跨端
- **定位**：替代或补充 Android，低成本覆盖 iOS 与微信生态
- **取舍**：小程序适合轻量搜题引流，但备案/合规要求更高

## 四、依赖关系（含**内容依赖**）

原有依赖图只画了"服务依赖"，遗漏了"内容依赖"——这是 RAG 空转的根因，本次补上：

```
   【内容依赖（隐藏地基，必须先建）】
   河南 · 高中 · 学科/教材版本/卷别  →  知识点本体(DAG)  →  题库/知识库(course_kb)
              │                                                │
              └────────────────┬───────────────────────────────┘
                               ▼
        ┌─────────────┐      ┌──────────────┐
        │ 学生端 App   │      │ Web 管理后台  │
        └──────┬──────┘      └──────┬───────┘
               │   HTTPS / JSON     │
               └─────────┬──────────┘
                         ▼
                 ┌──────────────────┐
                 │ Agent 后端服务    │  ← 地基，两端都依赖
                 │ (Orchestrator)   │
                 └────────┬─────────┘
                          ▼
        Kafka + PostgreSQL + Apache AGE(图谱) + pgvector(向量)
```

**关键点**：
1. **内容资产是隐藏地基**：没有题库与知识点本体，Agent 后端的 RAG、自适应、组卷全部无法工作。这是本次重排顺序的核心理由。
2. 第 3 项（后端服务）是服务地基，第 1、2 项都依赖它。
3. 第 4 项（小程序）是可选项，可在 App 验证后再决定。

## 五、开发分期（重排顺序，含验收标准）

> **新执行顺序**：定边界 → 灌内容 → 苏格拉底对话 → 自适应引擎 → 家长端
> 时间盒为**建议值**，需按团队实际规模确认；负责人为**角色占位**，需落实到人。

### P0｜立项与边界定义（建议 2 周）

| 项 | 内容 |
|---|---|
| **目标** | 锁定河南 · 高中 · 学科 · 教材版本 · 卷别，输出知识点本体，完成图谱 Schema 设计 |
| **关键任务** | ① 定首个学科（建议数学）+ 核对河南实际教材版本（数学：人教 A 版）+ 确认卷别（新高考 I 卷）；② 构建知识点 DAG 本体（含前后置依赖），**对齐人教 A 版高中数学章节结构**；③ 设计 AGE 图 Schema（知识点节点、依赖边、掌握度属性）；④ 定题库数据结构（题干/解析/答案/知识点标注/难度/题型/卷别，**须覆盖解答题与压轴题**） |
| **验收标准** | ✅ 边界文档定稿（河南 · 高中 · 3+1+2 · 数学 · 人教 A 版 · 新高考 I 卷）；✅ 知识点本体入库，规模 ≥ **300 个知识点**（对齐人教 A 版高中数学 必修+选择性必修，数量在 P0 实测校准），且有明确父子与前置关系；✅ 图 Schema + 题库 Schema 评审通过；✅ AGE 容器完成图谱初始化 |
| **负责人** | 教研负责人 + 后端 + 算法 |
| **依赖** | 无（起点） |

### P1｜内容地基：第一版题库与知识库（建议 4 周）

| 项 | 内容 |
|---|---|
| **目标** | 灌入第一版内容（河南 · 高中数学 · 新高考 I 卷），让 RAG 有东西可检 |
| **关键任务** | ① 导入题目（含解答题/压轴题），来源策略见下；② 每题打知识点标签 + 难度分级 + 卷别标签；③ 建向量索引（pgvector）与全文检索；④ RAG 检索链路打通（召回 → 重排 → 注入 Prompt）；⑤ 灌入配套讲解/考点文案进 `course_kb` |
| **内容来源策略（重要）** | 因河南 2026 首考新高考、本地新高考真题稀缺，内容以三类为主：**a) 新高考 I 卷其他省份真题**（河北/江苏/湖北/湖南/广东/山东等，与河南同卷，可直接复用）；**b) 新课标 + 人教 A 版教材例题/习题**；**c) 教研自产或采购题**。并用**河南教材章节顺序**组织 |
| **验收标准** | ✅ `course_kb` 入库题目 ≥ **3000 题**（覆盖新高考题型：选择/填空/解答，须含解答题与压轴题），100% 带知识点标注与难度；✅ RAG 检索可用，人工抽测 50 题的知识点召回准确率 ≥ **85%**（标准可调）；✅ `/similar` 能返回真正同类题 |
| **负责人** | 教研 + 算法 + 后端 |
| **依赖** | P0 完成 |
| **⚠️ 前置工程** | 补齐 `pgvector`（现状服务器只有 AGE，无向量库——见差距报告 G1） |

### P2｜苏格拉底引导式对话（Agent 默认模式）（建议 4 周）

| 项 | 内容 |
|---|---|
| **目标** | 把 `/solve` 从"直接给答案"改为"引导式提问"，成为 Agent **默认**行为 |
| **关键任务** | ① 重写 Orchestrator 的解题 Prompt 为苏格拉底模板（反问 → 渐进提示 → 最后才讲解）；② 加"直给答案"拦截逻辑（学生索要答案时先引导）；③ 接通 OCR/VLM 拍照识题（须适配高中**长题干 + 复杂数学公式**）；④ 结构化输出（考点/易错点/举一反三）走引导式呈现；⑤ 学生端对话 UI 支持多轮追问 |
| **验收标准** | ✅ 人工评测 20 道高中数学典型题，**"直接给出最终答案"的发生率 = 0**（必须先反问/提示）；✅ 多轮对话可稳定追问 ≥ 3 轮且上下文不丢；✅ 拍照识题准确率 ≥ **90%**（须覆盖长题干与复杂公式场景；标准可调）；✅ 直给答案仅在学生 3 次提示后仍不会时才触发 |
| **负责人** | 算法 + 后端 + App |
| **依赖** | P1 完成（RAG 提供知识点与同类题） |

### P3｜掌握度图谱 + 自适应路径（建议 4 周）

| 项 | 内容 |
|---|---|
| **目标** | 上线核心差异化能力：学生掌握度建模与自适应推题 |
| **关键任务** | ① 实现掌握度更新算法（答对/答错/遗忘衰减），须支持**解答题按步骤拆分到多个知识点**；② 基于图谱计算最近发展区 ZPD；③ 自适应推题引擎（难度自适应 + 变式题推荐）；④ 错题本 → 薄弱点定位 → 间隔重复复习计划；⑤ App 新增"知识图谱可视化 + 掌握度"页（展示个人掌握图谱） |
| **验收标准** | ✅ 学生做题后掌握度向量正确更新并持久化；✅ 推题 100% 落在 ZPD 内（已掌握知识点不再重复推送）；✅ 错题能自动回溯到前置薄弱知识点；✅ 解答题多步错误的知识点归因正确；✅ App 能可视化个人知识图谱与掌握度热力；✅ 小范围内测 ≥10 名**河南高中生**，练习量下降但掌握度提升（有效性验证） |
| **负责人** | 算法 + 后端 + App |
| **依赖** | P2 完成（需先有引导式对话收集交互数据） |

|---|---|---|
| **R1 内容资产获取成本超预期**（高中知识点多、题干长、解答题/压轴题占比高） | P1 卡住，后续全停 | 提前锁定内容来源（采购/开源题库/教研自产）；先备 500 题最小可用集验证链路，再扩到 3000 |

## 十、一句话总结

> 本计划书的核心修正：**先有内容与边界，再有 AI 能力；先把 Agent 变成"导师"（引导式），再让它变成"自适应引擎"**。
> 首个落地样例锁定 **河南省 · 高中 · 新高考 I 卷 · 数学（人教 A 版）**——选数学是因为它是全国 I 卷统一命题科目，一套内容可复用到全部 11 个新高考 I 卷省份（选考科目则是河南自主命题，复用率仅为 1）。
> 差异化押注 **知识点掌握度图谱驱动的自适应路径**——这是市场题库驱动产品中少见的能力，也是本系统值得做深的方向。

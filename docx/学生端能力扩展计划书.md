# 学生端能力扩展计划书（项目 · 功能开关 · 防疲劳提醒）

> **定位**：在《后台权限与系统集成任务计划书》（下称"RBAC 计划"）的权限基座之上，新增三项**学生端能力**：
> 1. **学生网页端可新建项目**（自学/专题工作区）
> 2. **管理员 / 区域管理员 / 学校 / 教师 可控制学生 App 与网页端的功能显示**（功能开关 / 模块可见性）
> 3. **学习防疲劳提醒**（护眼 / 休息提醒）
>
> 其中 #2（功能开关）是 #1 与 #3 的**总开关**——"项目"与"防疲劳"是否对学生可见，由功能开关按角色/范围控制。
>
> **创建日期**：2026-10-25
> **关联文档**：`后台权限与系统集成任务计划书.md`（权限引擎、角色矩阵、动态菜单，本计划的 #2 复用其 `require_perm` 与 T-AM2/T-AM7）、`学校配置大模型BYOM能力任务计划书.md`、`P2引导式对话与横向收尾任务计划书.md`
> **现状基线**：已核实 `web-backend` 无任何 `project`/`防疲劳`/`feature_switch` 实现；`student-app` 与 `web-frontend` 均无"项目""功能开关""防疲劳"页面——本计划为纯新增。

## 一、需求拆解（用户原话 → 系统能力）

| 用户要求 | 对应系统能力 |
|---|---|
| 学生网页端可以新建项目去做 | 学生网页端「我的项目」模块：项目 CRUD + 任务清单 + 进度；数据模型 `student_project` / `student_project_task` |
| 管理员、教师、学校等角色可以控制学生 App、学生网页端功能显示 | 功能开关（Feature Switch）系统：`feature_switch` + 按范围（global/region/tenant/class）覆盖；admin/region_admin/school/teacher 可切换；学生端 `GET /api/student/features` 按范围解析可见功能集 |
| 要有学习防疲劳提醒能力 | `anti_fatigue_config` + 客户端计时器：连续学习达阈值弹出休息/护眼提醒；受功能开关 `anti_fatigue` 管控 |

## 二、整体设计

### 2.1 学生网页端「项目」能力（#1）

**概念**：项目 = 学生自建的学习工作区（如"攻克电磁感应""高考数学压轴题专题"），内含任务清单、目标、关联知识点，可追踪进度。纯学生自建、自驱，不依赖教师派发。

**要点**：
- 归属：`student_id` + `tenant_id`（学校隔离，复用网关 `tenant_id`）。
- 功能入口：学生网页端「我的项目」菜单（受功能开关 `project` 管控，见 2.2）。
- 进度：由 `student_project_task.done` 聚合出完成度；可关联知识点（`kp_code` 可选，复用 `kb_knowledge_points`）。
- 不进 Web 管理后台菜单——它是**学生端功能**，不是管理员功能。

### 2.2 角色控制学生端功能显示（#2，核心开关）

**概念**：把"学生 App / 网页端"的每个可独立显隐的功能做成一枚**功能开关（feature key）**。管理员/区域管理员/学校/教师按各自管辖范围打开或关闭，学生端启动时拉取"对自己生效的开关集"，据此渲染入口与按钮。

**范围层级（解析优先级，越具体越优先）**：
```
class(教师班级)  > tenant(学校)  > region(区域)  > global(平台默认)
```
- `admin`：可设 global + 任意 region/tenant/class（全平台）
- `region_admin`：可设本 region（+ 其下 tenant/class）
- `school`：可设本 tenant
- `teacher`：可设本 class
- `parent` / `student`：**无控制权**（仅消费）

**平台维度**：每枚开关带 `platform` 字段（`app` / `web` / `both`）——可"网页端开、App 关"或反之。

**解析规则**：`effective = override[class] ?? override[tenant] ?? override[region] ?? override[global] ?? feature.default_on`。

**初始功能清单（feature key）**：
| feature_key | 名称 | platform | 默认 | 关联能力 |
|---|---|---|---|---|
| `project` | 我的项目 | web | 开 | #1 学生项目 |
| `anti_fatigue` | 防疲劳提醒 | both | 开 | #3 防疲劳 |
| `wrong_book` | 错题本 | both | 开 | 既有 |
| `group_paper` | 自动组卷 | both | 开 | 既有 |
| `knowledge_graph` | 知识图谱 | both | 开 | 既有 |
| `ai_tutor` | AI 辅导对话 | both | 开 | 既有 |

> 后续新增学生端功能都先注册一枚 feature key，即可被本系统管控。

### 2.3 学习防疲劳提醒（#3）

**概念**：学生连续学习达设定时长，客户端弹出"休息一下 / 远眺护眼"提醒，防止用眼疲劳。

**要点**：
- 开关：`anti_fatigue` feature key 控制总体可见（2.2）。
- 配置：`anti_fatigue_config` 存 `interval_min`（提醒间隔，默认 25）、`break_min`（建议休息时长，默认 5）、`message`（文案，可个性化）、`mode`（仅提醒 / 强制锁屏休息）。
- 触发：学生 App / 网页端在本地维护"连续学习会话计时"（从进入学习页/提交作答开始累计），达 `interval_min` 即弹提醒；尊重 #2 开关与配置。
- 服务端可辅助：学习会话 API 记录 `session_start`，超时由客户端计时为主（降低服务端压力），教师/学校可在配置里调阈值。
- 不收集敏感数据，仅本地计时 + 服务端下发的配置参数。

### 2.4 三者关系

```
[功能开关 feature_switch]  ——总闸——
        ├── project (开/关) ──► 学生网页端「我的项目」显隐
        └── anti_fatigue (开/关) ──► 防疲劳提醒是否启用
角色控制：admin / region_admin / school / teacher 按范围切换上面每枚开关
```

## 三、数据模型（PostgreSQL，扩展现有库）

```sql
-- 9) 学生项目（#1）
CREATE TABLE student_project (
    project_id   VARCHAR(64) PRIMARY KEY,
    student_id   VARCHAR(64) NOT NULL,           -- App/网页端学生用户
    tenant_id    VARCHAR(64) NOT NULL,           -- 学校隔离
    title        VARCHAR(255) NOT NULL,
    description  TEXT,
    goal         TEXT,
    kp_code      VARCHAR(64),                    -- 可选：关联知识点(DAG code)
    status       SMALLINT     DEFAULT 1,         -- 1 进行中 / 0 归档
    created_at   TIMESTAMPTZ  DEFAULT now(),
    updated_at   TIMESTAMPTZ  DEFAULT now()
);
CREATE INDEX ix_project_student ON student_project(student_id, tenant_id);

-- 10) 项目任务清单（#1）
CREATE TABLE student_project_task (
    task_id    VARCHAR(64) PRIMARY KEY,
    project_id VARCHAR(64) NOT NULL REFERENCES student_project(project_id),
    title      VARCHAR(255) NOT NULL,
    done       BOOLEAN     DEFAULT FALSE,
    due_at     TIMESTAMPTZ,
    sort       INT         DEFAULT 0
);

-- 11) 功能开关定义（#2）
CREATE TABLE feature_switch (
    feature_key   VARCHAR(64) PRIMARY KEY,        -- project / anti_fatigue / ...
    feature_name  VARCHAR(128) NOT NULL,
    platform      VARCHAR(16) NOT NULL DEFAULT 'both', -- app / web / both
    default_on    BOOLEAN     DEFAULT TRUE,
    description   TEXT
);

-- 12) 功能开关按范围覆盖（#2：谁在什么时候关了/开了什么）
CREATE TABLE feature_switch_override (
    feature_key VARCHAR(64) NOT NULL,
    scope_type  VARCHAR(16) NOT NULL,             -- global / region / tenant / class
    scope_id    VARCHAR(64),                       -- 对应 region_id / tenant_id / class_id；global 为空
    enabled     BOOLEAN     NOT NULL,
    updated_by  VARCHAR(64),
    updated_at  TIMESTAMPTZ DEFAULT now(),
    PRIMARY KEY (feature_key, scope_type, scope_id)
);

-- 13) 防疲劳配置（#3）
CREATE TABLE anti_fatigue_config (
    scope_type  VARCHAR(16) PRIMARY KEY,           -- global / region / tenant / class
    scope_id    VARCHAR(64),
    enabled     BOOLEAN     DEFAULT TRUE,
    interval_min INT         DEFAULT 25,           -- 连续学习提醒间隔(分钟)
    break_min   INT          DEFAULT 5,            -- 建议休息(分钟)
    mode        VARCHAR(16)  DEFAULT 'remind',     -- remind 仅提醒 / enforce 强制休息
    message     TEXT         DEFAULT '该休息一下啦，远眺放松眼睛，保护视力~'
);
```

## 四、角色 × 功能开关控制矩阵（#2 谁能动）

| 角色 | 可设范围 | 可管控平台 | 典型动作 |
|---|---|---|---|
| **admin 管理员** | global + 任意 region/tenant/class | app/web/both | 平台级总开关，定义默认 |
| **region_admin 区域管理员** | 本 region（+ 其下 tenant/class） | app/web/both | 本区域统一开关策略 |
| **school 学校** | 本 tenant | app/web/both | 本校 App/网页端功能显隐 |
| **teacher 教师** | 本 class | app/web/both | 本班功能微调（如关闭某班组卷） |
| parent 家长 | — | — | 仅消费 |
| student 学生 | — | — | 仅消费（看自己生效的开关集） |

> 学生端读取的是**解析后的生效集**（2.2 优先级），不暴露"谁关的"。

| **T-S1** | 学生项目数据模型 + 迁移：`student_project` / `student_project_task`；种子 feature_switch（6 枚默认开） | RBAC T-AM1（tenant 隔离） | 中 |

## 六、与 RBAC 计划的衔接

| 本计划能力 | 复用 RBAC 计划 | 说明 |
|---|---|---|
| #2 功能开关后台「功能开关」菜单 | RBAC §四 角色矩阵、T-AM2 `require_perm`、T-AM3/T-AM4 菜单与授权 | 新增一枚权限 `system:feature:manage`，仅 admin/region_admin/school/teacher 持有；菜单由 T-AM7 动态加载 |
| #2 学生端拉取开关 | RBAC §2.3 权限引擎（Redis 缓存） | `/api/student/features` 解析可复用权限缓存机制，授权变更即时生效 |
| #1 学生项目 | RBAC `tenant_id` 隔离 | 项目数据按 `tenant_id` 由网关强制隔离，与现有多租户一致 |
| 角色范围（region/tenant/class） | RBAC §2.1 双隔离维度 | `feature_switch_override` 的 scope 与 RBAC 的 region/tenant 体系对齐 |

**权限码新增**：`system:feature:manage`（功能开关管理，归 admin/region_admin/school/teacher）。

## 七、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 学生端未读开关就渲染 | 功能关了仍显示 | App/网页端**启动时强制拉 `/api/student/features`** 再渲染；开关变更后下次启动/定时刷新生效 |
| 范围覆盖冲突（教师开、学校关） | 学生看到矛盾状态 | 严格按 2.2 优先级解析，只取最具体一层，结果唯一 |
| 防疲劳变"强制锁屏"引发抵触 | 体验差 | `mode` 默认 `remind`（仅提醒），`enforce` 仅作可选；文案可配置 |
| 教师控制粒度过细难维护 | 运维负担 | class 级为最细；默认继承上层，仅例外时覆盖 |
| 项目数据跨租户泄露 | 高 | `student_project` 强制 `tenant_id` + 网关 `require_tenant`，DAO 层注入 |

## 八、验收标准

- ✅ 学生网页端可新建/编辑/归档项目，含任务清单与进度；数据按 `tenant_id` 隔离。
- ✅ 管理员/区域管理员/学校/教师 均可在后台「功能开关」按各自范围切换学生 App / 网页端功能显隐；parent/student 无此入口。
- ✅ 关闭 `project` 开关后，学生网页端「我的项目」入口消失；关闭 `anti_fatigue` 后两端均不弹防疲劳提醒。
- ✅ 教师关闭本班 `group_paper`，该班学生 App 与网页端均不显示自动组卷；同校其他班不受影响（scope 隔离生效）。
- ✅ 学生连续学习达 `interval_min`，App 与网页端弹出护眼/休息提醒；`mode=remind` 仅提醒不阻断。
- ✅ 所有开关变更经 RBAC 权限 `system:feature:manage` 校验，越权返回 403。

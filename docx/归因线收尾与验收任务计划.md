## 二、任务详述

### T1 · 物理 Pass B 步骤讲解补跑

**目标**：`course_kb_steps.explanation` / `error_reason` 物理 303 步由 0 → 满，使物理从"判分可用"升级为"讲解可用"。

**实现要点**
- 复用已验证脚本 `agent-backend/scripts/gen_pedagogy.py`，`--subject 物理 --q-only`（KP 卡数学已完成，物理本轮只补步骤）。
- **必须从 `agent-backend/` 目录启动**（`load_dotenv` 按 cwd 找 `.env`，否则读不到 LLM 配置、表现为"假挂起"）。
- 先 `--q-limit 5` 冒烟看输出质量与耗时，再全量；跑批前确认 106 隧道存活（`ssh -N -L 15432:106.12.25.5:5432 137`）。
- 启动后核对进程数，**避免重复进程**（历史上多次同参双开，双倍消耗 LLM 额度）。
- 用已验证模型 `deepseek-v4.1-flash-1017`；超时 180s、不设 `max_tokens`（推理模型设小会返回空）。
- 跑完接 `classify_error_type.py` 打七分类，再查一次 unknown 率。

**验收标准**
- 物理 `explanation` 非空 ≥ 95%（≥288/303）；失败项有明确错误日志而非静默跳过。
- 物理 `error_type` 英文七类占比 100%，unknown ≤10%。
- 抽 10 条教师人工过目，语义与物理学科表述相符（不出现数学化套话）。

**风险**：物理题含公式/单位，LLM 易输出 LaTeX 与纯文本混排 → 需约定输出格式并在抽检时统一。

---

### T2 · 错题本自动写入链路（**优先级最高**）

**目标**：判分产生错因后自动落一条 `wrong_questions`，带 `content_hash` + `wrong_step_no` + `error_type` + `attribution_source` + `evidence`，使 S5④ 的 correction / 知识点卡展示有数据源。

**实现要点**
- 落点：`web-backend/app/workers/student_event_worker.py` 的 `handle_events()`（当前只写 `student_step_errors`），或 `app/services/learning.py` 的 `record_step_error()` 内一并写。建议放 worker，保持 service 单一职责。
- 触发条件：`correct is False` **且** `need_process is not True`（过程缺失不算做错，避免"没写过程"被记成错题污染掌握度）。
- 去重：同一 `(student_id, content_hash, wrong_step_no)` 已存在则更新 `created_at` / 计数，不重复插（幂等，可重复消费）。
- 题干回填：`course_kb.stem`（按 `content_hash` 关联），知识点取 `course_kb.knowledge_points`。
- 写 `attribution_source`（map/llm/unknown）便于 S6 统计确定性归因占比。

**验收标准**
- 造 3 学生 × 10 事件（含 2 条 `need_process=true`）消费后：`wrong_questions` 新增条数 = 错题事件数 − need_process 条数。
- 重复消费同一批事件，错题本条数不增长（幂等）。
- 管理端 `GET /api/admin/wrong-questions?student_id=...` 返回含 `correction`（这一步应该怎么做）、`step_text`、KP 卡 `understanding/memory`。
- 新增单测 ≥5 例（`need_process` 不入库、幂等、correction 抽取）。

**风险**：`content_hash` 缺失的事件无法关联步骤 → 直接入库但 correction 为 null，接口需容忍。

### T3 · 数学 2 道解答题补跑

**目标**：补完挂起的 2 道解答题（`content_hash` 前缀 `c524576e…` / `ff72e92a…`，各 3 步），数学步骤讲解趋近 100%。

**实现要点**
- 此前 3 次超时放弃 → 单题单跑（不走全量），必要时换推理能力更强的模型或放宽超时到 300s。
- 若仍失败，记录失败原因并给出"人工补录"降级路径：由教师直接在库中填 `explanation`。

**验收标准**：2 题 6 步 `explanation` 非空；或明确标记为"人工补录"并列入教师待办。

**风险**：低。属收尾性质，不阻塞任何下游。

### T4 · S6 评测脚手架（不依赖真实数据，可立即做）

**目标**：试点数据一到、教师填完金标准，即可一键出三张评测表。

**交付物**
1. **金标准模板**（CSV）：`content_hash / step_no / 学生作答过程 / 金标准首错步骤 / 金标准错因 / 评分人A / 评分人B / 仲裁结果` ——双人背靠背 + 仲裁列。
2. **评测脚本** `agent-backend/scripts/eval_attribution.py`：读金标准 → 跑 `judge_v2.judge()` → 输出三张表：
   - 客观题查表命中率（应 ~100%，零 token）
   - 解答题首错步骤对齐准确率（S6 指标要求 ≥85%）
   - 错因分类准确率 + unknown 率（要求 ≤10%）
   - 附：一致性指标（评分人 A/B 的 Cohen's κ）
3. **结果归档目录** `eval/2026-试点校-批次N/`，含原始金标准、脚本输出、结论 Markdown。

**验收标准**
- 脚手架可用合成数据自测跑通（不依赖真实库），输出三张表格式稳定。
- 金标准模板字段被教师确认无歧义（首错步骤定义、错因七类中文名与 taxonomy 对齐）。

**风险**：金标准标注需要教师工时，属外部依赖；脚手架本身可先交付。

## 三、执行顺序建议

1. **T2（错题本链路）** —— 唯一的功能真空缺，工程量小（半天）、收益直接（老师端立刻有内容）。
2. **T1（物理讲解）** —— 跑批为主，启动后可并行做别的，是内容侧最大缺口。
3. **T4（S6 脚手架）** —— 不依赖真实数据，现在做完后面零等待。
4. **T3（2 道解答题）** —— 收尾，随时插空。
5. **T5（试点开跑）** —— 外部排期，前四项完成即具备开跑条件。

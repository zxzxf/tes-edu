一张图串起 用户端 → 网关 → 双后端 → AI 引擎 → 数据层（Go 网关 + Python 双后端 + Kotlin 安卓）
用户层 网关层（边界防护） 服务层 引擎层 工具/检索层 数据层
L1 用户层 Kotlin (Android) · Vue3 (Web)

📱 Android App C 端学生

  • 文本/语音输入
  • 拍照识题（OCR 上传）
  • 讲解展示（公式渲染）
  • 触类旁通推荐列表
  • 知识图谱可视化
  • 背诵卡 / 错题本（Room 离线）

🖥️ Web 管理后台 B 端教研/教务

  • 教研内容管理（知识库导入）
  • 学情看板 / 薄弱点诊断
  • 错题本、自动组卷 / 周测
  • 教师端：批改与布置
  • 家长端：周报推送
  • 互动讲解配置 / 多模态 / 合规审核
▼ HTTPS / JSON（仅暴露一个公网入口）
L2 网关层（Go） Go · 单二进制 · 可选 APISIX/Kong

统一边缘网关

  • 鉴权（JWT / RBAC 校验）
  • 限流 · 熔断 · 防刷
  • 请求路由（app / admin 分流）
  • 审计日志（合规 #8 落点）
  • 输入校验 / 内容安全过滤

▼ 按路径转发（后端不再直连公网）
L3 服务层（Python / FastAPI） Python · FastAPI · 双服务同栈

Agent 后端 /api/app · /solve

  • Orchestrator：意图路由
  • 工具调用 / Prompt 模板
  • 解题 + 分步讲解
  • 触类旁通出题
  • 拍照解析（图→题→解）

Web 后端 /api/admin

  • 教研内容 / 知识库管理
  • 学情分析 / 薄弱点聚合
  • 自动组卷 / 周测生成
  • RBAC 角色权限
  • 教师批改 / 家长周报
▼ 调用推理与检索能力
L4 推理 / 多模态引擎 LLM · VLM · OCR

LLM 解答引擎

  • 通义千问 / DeepSeek（私有化可部署）
  • 解题、讲解、组卷、互动引导

VLM 多模态

  • 图片理解、版面切题、手写识别
  • 公式 LaTeX 识别

OCR 引擎

  • PaddleOCR：印刷 / 手写文字识别
  • 拍照题面抽取
▼ 检索增强（RAG / 图谱）
L5 工具 / 检索层 RAG · 知识图谱

RAG 检索器

  • 向量检索（pgvector）
  • 知识点 / 例题 / 解析召回
  • 防幻觉上下文注入

知识图谱查询

  • Apache AGE / Neo4j（Cypher）
  • 知识点关联 / 复习路径
  • 触类旁通 / 记忆曲线
▼ 异步管道 + 持久化
L6 数据层 Kafka · PostgreSQL

Kafka 消息总线

  • course_kb_ingest：知识库入库
  • drill_sync：背诵卡同步
  • student_logs：学情事件流（异步管道）

PostgreSQL（真实数据源）

  • course_kb / knowledge_points 知识点
  • embeddings（pgvector）
  • kg_edges（AGE/Neo4j 图谱）
  • drill_cards / student_logs
设计要点： ① 两个端共用一套内核——Android 与 Web 后台都只经过 Go 网关，再分流到 Agent 后端 / Web 后端，二者均 Python/FastAPI，仅维护 Go + Python 两种运行时； ② 网关是唯一公网入口，鉴权·限流·审计集中在 L2，后端服务不直连外网，合规（#8）的"访问控制/访问审计"在网关层统一承载； ③ Kafka 仅作异步管道，PostgreSQL 才是真正数据源（向量 + 图谱 + 业务表同库或分库皆可）； ④ 私有化部署为相对巨头的核心差异化优势——数据不出域、可学校/机构本地落地。
PG 版本提示：当前 PG 11.2 下 pgvector 需 PG 13+，建议新起 PG 16（Docker pgvector/pgvector:pg16）承载向量+图谱，老库保留业务数据。

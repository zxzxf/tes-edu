# tes-edu 官网项目 · 实施计划书

> 版本：v1.0 ｜ 日期：2026-11-19 ｜ 状态：待评审
> 定位：新增独立子项目 `official-site/`——tes-edu 课程智能平台的**对外营销官网**（静态站），面向学校/机构/家长讲清"我们是谁、能做什么、怎么联系"，与现有 B 端管理后台、C 端学生应用并列，是仓库第三个前端形态。
> 原则：**纯静态、重 SEO、品牌同源**（紫渐变+橙粉设计系统）、不引入 Web 框架、不动现有网关链路。

|---|---|---|

| 已有原型 | `official-site/index.html`（六段结构完整）+ `styles.css`（品牌令牌+全站样式+三档响应式已写完）；`app.js`/assets/SEO 文件未落盘 | 计划书定稿后如需动工，阶段 1 只剩 app.js、assets、SEO 套件与浏览器实测调优 |
| 公网入口 | cloudflared 隧道 → 宿主机 :80 → edu-lb(nginx) → gateway×2 → backends；`web-front` 独立 nginx 容器（--network-alias web-front） | 官网复用同一模式：独立 nginx 容器 + 别名，**不进网关**（营销站无鉴权需求，也不该蹭业务网关限流/审计） |

| 云服务 | 官网表单如需收集线索，可后置接 web-backend 一张 lead 表 | MVP 先 mailto + 企微二维码占位，不做表单后端 |

## 二、目标与范围

### 本期做（v1 上线标准）
1. 六段式单页官网：首屏 Hero → 产品三端 → 核心能力 → 数据与教研 → 安全可信 → 联系/CTA + 页脚。
2. 品牌视觉系统：延续管理端「紫渐变 + 橙粉 + 白卡片 + 粉白底」，独立成 `styles.css` 设计令牌（CSS 变量）。
3. SEO 基础：语义化标签、meta description、Open Graph/Twitter 卡片、`sitemap.xml`、`robots.txt`、结构化数据（Organization/SoftwareApplication JSON-LD）。
4. 响应式：1280 / 768 / 390 三档断点，移动端汉堡菜单。
5. 部署上 137：独立 nginx 容器 `edu-official-front`，静态资源 gzip + 长缓存（按文件指纹）。
6. 无障碍与性能：Lighthouse 目标 ≥90（Performance/SEO/Best Practices），首屏零 JS 依赖（JS 仅菜单/滚动增强）。

### 本期不做
- 不做 CMS/在线改内容（更新=改代码重发版，频率低够用）。
- 不做多语言 i18n（先中文；英文版留接口位 `lang="zh-CN"` 结构）。
- 不做表单后端与线索管理（先 mailto/电话/二维码；量大再立 lead 表任务卡）。
- 不做产品截图实拍/视频（P0 用原型示意卡，素材到位后替换）。
- 不进网关、不挂业务子域之外的鉴权链路。

## 三、技术方案

```
official-site/                ← 新增顶层子项目（与 web-frontend 平级）
├── index.html                首屏六段（已有原型）
├── styles.css                设计令牌 + 全站样式（待建）
├── app.js                    菜单开合/平滑滚动/进入动画（待建，渐进增强）
├── assets/                   logo、产品示意、favicon、og-cover（待补）
├── sitemap.xml / robots.txt
└── Dockerfile + nginx.conf   edu-official-front（仿 front_nginx_20261112.conf 精简版）
```

- **为什么纯静态不用框架**：官网=内容展示型站点，SSR/SPA 都是过度设计；纯静态天然快、天然 SEO、零依赖零构建故障面，发版=传文件。
- **渠道路由与业务隔离**：官网容器只在 edu-net 挂静态目录，不 proxy 任何后端；即使官网被打挂也不影响业务网关。
- **域名与入口两方案（阶段 0 二选一）**：
  - A. **有域名+备案**：Cloudflare DNS → CF Tunnel 新增 public host 指向 137 官网容器端口 → 正式域名直达，HTTPS 由 CF 边缘证书解决（推荐，最省事）。
  - B. **暂无域名**：先在现有隧道下挂 `/` 路径之外的独立子域试用地址（如 official.xxx.trycloudflare 形态）给内部看效果，正式上线等备案。

## 七、风险与备忘

- **备案是硬前置**（方案 A）：未备案域名指向国内服务器会被腾讯云阻断；CF Tunnel 形态暂无此问题，但正式上线的规范形态应有自有域名。
- **内容合规**：教育类对外宣传避免"提分保证""升学率"等承诺性用语（《广告法》教育培训条款）；文案只陈述产品能力与实测数据。
- **别把内部系统能力写上官网**：股票盯盘、推送中心属内部工具，未成产品前不进对外物料。
- **与业务隔离是底线**：官网是公网攻击面最大的入口，独立容器、零后端连通、零 Cookie/登录态，即使被刷也只烧静态带宽。
- **磁盘/内存**：nginx:alpine + 静态文件增量 <50MB，137 当前 55% 占用无压力。

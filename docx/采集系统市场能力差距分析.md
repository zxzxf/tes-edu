# 采集系统市场能力差距分析

> **文档定位**：把《采集服务化拆分设计草案.md》与 2026 年主流采集/爬虫平台做横向对比，明确草案"按通用采集平台标准"缺了哪些能力，并给出补齐优先级。
> **版本**：v1.3 — 2026-11-12（整理"采集任务 vs 市场采集平台"结论速览，明确 P1 仍空缺）；v1.2 = 137 发版 + 真站点端到端验收后复核
> **对比基准**：Apify、Bright Data、Oxylabs、Diffbot、Octoparse、Firecrawl、Zyte、Scrapy 生态（Scrapy-Playwright / Scrapy-Redis）、Crawl4AI / ScrapeGraphAI（来源：2026 年公开评测与厂商文档）
> **关联文档**：`docx/采集服务化拆分设计草案.md`（服务化选型）、`docx/采集任务方案计划书.md`（M5 功能方案）

---

## 0. 总体定调

本草案的定位是**领域特定的最小可用采集**（课程素材 → `course_kb`），**不是**通用爬虫平台。因此下文大量"缺失"是"按通用采集平台标准看缺"，不代表都要补——除非将来把采集做成平台化产品（即草案 §1.2 所述"平台化诉求"，那时 B 形态 + 下列能力才需要）。

**一句话结论**：草案在"抓取引擎（JS 渲染 / 反爬 / 代理）、数据质量与漂移检测、分布式、可观测告警、连接器生态、导出多样性、审计溯源"等块相对 2026 年主流平台仍系统性缺失；**AI 抽取（M5-2）与 `web` 源修复两项 P0 已于 2026-11-12 在 137 完成真实站点端到端验收**，另顺带补齐浏览器 UA 与重定向逐跳 SSRF 复查。

> **v1.2 更新（2026-11-12）**：两项 P0 已从"代码层落地"推进到**生产可用**——137 发版并开启 `CRAWL_LLM_EXTRACT_ENABLED`，经真实网关 + pilot 租户跑通 3 场景（`web`/pep.com.cn、`url`/w3schools、`file`/含题样本 `fetched/inserted=2/2`），无题页面不编造、验收数据零残留；完整套件 **645 passed**。真站点验收还暴露并修复了两个抓取缺陷：httpx 默认 UA 被 w3schools 403（已补浏览器 UA）、`follow_redirects=True` 仅校验首跳导致 302 到云元数据可绕过 SSRF（已改逐跳复查）。**仍存差距**：抽取仅支持单页静态 HTML（无 JS 渲染 / 无代理池 / 无 CAPTCHA）、缺模式漂移检测与抽取质量评估、无分布式与告警落地。详见 `docx/采集任务方案计划书.md` §8.4。
>
> **v1.3 更新（2026-11-12）**：应需求把"我们的采集任务 vs 市场采集平台，缺什么"整理成**结论速览**（见 §0.1）。新增基线复核：当前采集器为**领域特定最小可用采集**（4 类源 `file/bank_pack/url/web`、`web` 源带 SSRF 出站防护 + 浏览器 UA、LLM 抽取已生产可用）；曾尝试在 A 形态内落地 `app/crawl_service/quality.py`（质量评估 + 漂移检测），后回滚，**P1 两项仍空缺、未进代码库**，与本节判定一致。

### 0.1 结论速览：采集任务 vs 市场采集平台

**基线（我们已具备）**：课程素材 → 抓取 → LLM 结构化抽取 → `content_hash` 去重 → 落 `course_kb` → 教研审核发布。已接通 `file / bank_pack / url / web` 4 类源；`web` 源带 SSRF 出站防护（重定向逐跳复查）+ 浏览器 UA；`llm_extract.py` 已用真实模型端到端真验（pep / w3schools / 含题样本 3 场景全绿）。

| 维度 | 市场能力代表 | 我们现状 | 缺口判定 |
|------|--------------|----------|----------|
| **抓取引擎** | Apify / Bright Data / Playwright | 仅 httpx 抓静态 HTML；基础 UA + SSRF | **几乎全缺**：JS 渲染、代理池、指纹/CAPTCHA、增量/变化检测 |
| **解析抽取** | Firecrawl / Diffbot / Crawl4AI | ✅ LLM 结构化抽取已生产可用 | ⚠️ 缺**数据质量关卡**、缺**模式漂移检测** |
| **平台工程** | Scrapy-Redis / Airflow / Prometheus | cron + `scheduler_loop`；`/metrics` 仅回数据 | **缺**：可观测告警、DAG/backfill、分布式、死信队列 |
| **生态集成** | Apify Store / Airbyte / Octoparse | 5 类源 + 单 sink（`course_kb`）+ REST | **全缺**：连接器市场、多 sink 导出、无代码、API/MCP |
| **合规治理** | SOC2 / GDPR / 企业级溯源 | SSRF + 版权清单元（清单仍缺） | **缺**：审计溯源、robots、PII 脱敏、保留策略 |

**我们反而领先（市场通用系统没有）**：出站 SSRF 防护（双重复查 host+IP）、单写者一致性治理（course_kb 仅 web 写）、知识点 DAG 归并 + 教师审核发布流、预算停止 + 租户隔离。

**最该补的两项（P1，A 形态内可落地、不依赖平台化）**：
1. 模式漂移告警 + 抽取质量评估（字段完整率/重复率/可疑项 + 跨 run 产出率突变）—— 弥补"源站改版 / 模型降级无感知"。
2. 可观测告警落地（失败 / 超预算真正通知人）。

> 其余 JS 渲染 / 代理、分布式、连接器市场、审计溯源均属**平台化 B 形态**诉求，当前领域场景用不上，不必现在补。

## 1. 采集引擎（抓取侧）—— 几乎全缺

| 市场能力 | 代表产品 | 我们草案 | 缺口 |
|----------|----------|----------|------|
| **JS 动态渲染 / 无头浏览器** | Apify Web Fetch「renders JavaScript」、Scrapy-Playwright、Playwright / Puppeteer | `safe_fetch_url` 仅 httpx 取静态 HTML；`web` 源已修为走 SSRF URL 抓取（2026-11-12） | **缺**：抓不了 SPA / 登录后 / 无限滚动页面 |
| **反爬与代理基础设施** | Bright Data「Web Unlocker」、Oxylabs 住宅/手机 IP 池、指纹 / CAPTCHA / Cloudflare·Akamai·DataDome 对抗 | 出站 SSRF 防护（含重定向逐跳复查）+ **浏览器 UA**（真站点验收发现默认 UA 被 403 后补上）；无代理池 / 指纹 / CAPTCHA | **部分补齐**：基础 UA 反爬已解决；代理轮换、指纹、验证码、限流退避仍缺 |
| **增量采集 / 变化检测** | Browse AI「change detection + 历史记录」 | 每次全量重抓，无 etag / last-modified / 断点续传 | **缺**：重复源重复抓、浪费预算 |

---

## 2. 解析与抽取（抽取侧）—— 核心硬缺口

| 市场能力 | 代表产品 | 我们草案 | 缺口 |
|----------|----------|----------|------|
| **AI / LLM 结构化抽取** | Firecrawl（LLM-ready Markdown）、Apify「AI Web Scraper 自然语言→结构化」、Diffbot（ML 实体 + 知识图谱）、Crawl4AI / ScrapeGraphAI | ✅ 已实现 `llm_extract.py`（清洗→提示词→稳健解析→schema 校验），**137 已开启并完成真站点端到端验收**（含题样本 `2/2` 真入库、无题页面不编造）；仍仅静态 HTML | **部分补齐**：核心能力可用，产品化成熟度（JS 渲染、代理、质量评估、开箱即用）仍落后 |
| **数据质量关卡** | 企业级：schema 校验、异常检测、跨 run 去重、字段完整性评分、**模式漂移检测** | 仅 `content_hash` 去重 + 中→英映射，无字段级校验、无漂移告警 | **缺**：脏数据直接进 draft、源站改版无感知 |

---

## 3. 平台工程（运维侧）—— 部分缺

| 市场能力 | 代表产品 | 我们草案 | 缺口 |
|----------|----------|----------|------|
| **分布式 / 水平扩展** | Scrapy-Redis、K8s 云原生、Apify 自动扩缩 | B 形态也只是单容器 | **缺**：高并发 / 大规模抓取 |
| **编排与调度成熟度** | Airflow / Prefect、集中编排平台、DAG / backfill / 重试策略 | 简单 cron + `scheduler_loop`，无 DAG / 增量 / 回溯 | **部分缺** |
| **可观测性** | Prometheus + Grafana、per-target 仪表盘、告警到 on-call、新鲜度监控 | 仅 `/metrics` 接口返回，无外部监控 / 告警 | **部分缺**：失败 / 超预算只打标不通知人 |
| **死信队列 / 单条失败隔离** | X-Byte「自动校验标记不完整数据」 | `run.error` + retry，无 DLQ、无单条隔离 | **缺** |

---

## 4. 生态与集成 —— 全缺

- **连接器 / 模板市场**：Apify Store 数千个 Actor、Airbyte 350+ 连接器、Octoparse 模板。我们仅 5 种 `source_type`，非结构化还没接通。
- **存储 / 导出多样性**：S3 / BigQuery / Snowflake / Kafka / CSV·JSON·Parquet / Webhook / Google Sheets。我们单一落 `course_kb`。
- **无代码 / 可视化**：Octoparse、Browse AI 点选训练。我们只有 `/parse` 接口。
- **API / MCP / SDK 生态**：Apify MCP、Firecrawl API。我们仅 REST 端点。

---

## 5. 合规治理 —— 缺审计溯源

- **审计级溯源（provenance）**：市场企业级要求"每字段回溯 URL + 时间戳 + 页面版本"。我们无。
- **robots.txt 遵守 / PII 脱敏 / 数据保留策略**：市场标配（GDPR / CCPA / SOC2）。我们只有 SSRF + 版权清单位（清单本身仍缺失）。

---

## 6. 我们反而领先的（领域特定优势，市场通用系统没有）

- **出站 SSRF 安全防护**（双重复查 host + 解析 IP）——很多商业爬虫反而忽略。
- **单写者一致性治理**（`course_kb` 仅 web 写、agent 只读）——针对本场景的单一数据源约束。
- **知识点 DAG 归并 + 教师审核发布流**——业务特定图谱，通用采集器无此概念。
- **预算停止 + 租户隔离**——贴合按租户 / 按任务的成本与隔离诉求。

## 决策

**不引入 Apache AGE，固化"关系表 DAG"方案（方案 A）。**

知识点图谱继续由 `kb_knowledge_points`（435 节点）+ `kb_kp_prerequisites`（435 边）承载，
图遍历统一走递归 CTE / Python 侧 `walk_up`（T-B2 `mastery.py` 已有实现）。
P0 DoD「图谱初始化」以 **T-B1 只读验收脚本**（覆盖度 / 悬空边 / 无环 Kahn / 核心标记四组校验，
106 真实库 435 节点 / 435 边 / 148 core 全 PASS）作为**等效验收**，不再要求 AGE 容器。

## 依据

1. **规模不必要**：当前 435 节点 / 435 边（章节级层级链），递归 CTE 毫秒级返回；
   AGE 的收益要到"万级节点 + 高频图遍历"才显著，届时收益/成本比才成立。
2. **运维风险为零容忍项让路**：106 为 PG16，需评估 AGE 1.5.x 与 PG16 兼容性、容器内编译安装、
   存量数据迁移到图标签的Schema 风险；当前 P3 关键路径（T-B2 已交付、T-B3 ZPD）不依赖 AGE。
3. **验证已就绪**：T-B1 四组校验 + 148 core 标记证明现有关系表是合法 DAG，
   算法层（T-B2 掌握度上溢/回溯）已在真实表结构上跑通单测与只读探针对账。
4. **计划书共识**：P1 计划书 T-B4 节明确"默认走方案 A，方案 B 仅在真实数据量证明
   递归 CTE 成为瓶颈时启动"。

# 题库产能提升方案（T-CAP 系列）

> **编写日期**：2026-10-29
> **目的**：在现有《总任务清单与排期计划》之外，单列"**如何提高出题效率与产能**"的专项方案，把"213 题 → 验收 3000 题"的供给缺口，从"纯人工录入+标注+校验"转为"AI 预做、人只校 + 变式复用"的流水线。
> **对接关系**：本方案是 §3.10（T-HW 作业闭环 M0/M5）、§3.11（T-PQ 组卷）的**产能前置使能层**——M0 是题库地基、M5 是采集、T-PQ 是消耗端；本方案让"供给"这条链足够宽，三者才跑得起来。
> **已落地积木（直接复用，不重造）**：`parser.py`（清洗归一✅）、`compose.py`（按知识点抽题/变式推荐✅）、`equiv.py`（等价判定纯函数✅）、`gen_pedagogy.py`（**LLM 规模标注已实证：数学+物理步骤归因全量跑通**✅）、`import_bank.py`（入库✅）。

---

## 一、产能瓶颈诊断（基线）

| 项 | 现状 | 验收目标 | 缺口 |
|---|---|---|---|
| 题库总量 | 213 题（数学 123 + 物理 90） | 3000 题 | ≈2787 题 |
| 年级覆盖 | **全是高三**真题，高一/高二 0 题 | 高一~高三 | 年级维度全缺 |
| 题型平衡 | 填空仅 21 道 | 选择/填空/解答合理配比 | 填空极缺 |
| 难度梯度 | 难度 1 仅 3 道 | 易:中:难 ≈ 3:5:2 | 低难度极缺 |
| 标注覆盖 | 部分题缺多知识点标签 | 100% 标注（知识点+难度+卷别） | 标注产能缺口 |

**时间花在哪**：一道题进库要过 采集/录入 → 结构化清洗 → 标知识点+难度+卷别 → 校验答案/去重。其中**标注与校验是人工重灾区**，纯人工约 **15 分钟/题**。这也是《市场对比与差距分析》点名的"标注产能与成本"生死线。

## 二、五大提效杠杆

| # | 杠杆 | 做法 | 复用现有 | 提效 |
|---|---|---|---|---|
| **L1 采集自动化** | 真题/教材爬取 pipeline 自动入库 `draft` | 源管理→解析→知识点拆分→审核 | M5（§3.10.6，已规划 21d） | 解决"题从哪来" |
| **L2 录入结构化** | OCR（手写/公式 LaTeX）+ 批量导入 + 解析 | 对接 `parser.py` | `parser.py`✅ | 录入提速 5–10× |
| **L3 标注自动化（最大杠杆）** | **LLM 预标知识点/难度/题型/卷别 → 人只校** | 模型打草稿标签，人做"确认/改" | `gen_pedagogy.py`✅（已实证 LLM 规模标注可行） | 标注人工 ↓70–80% |
| **L4 变式复用（产能倍增器）** | **1 道真题干 → N 道变式**（换数/换景，同 KP、答案已知） | LLM 生成变式 + `equiv.py` 自动校验 | `equiv.py`✅、`compose.py`✅（变式推荐） | 有效产能 ×3–5 |
| **L5 校验自动化** | 答案自洽 + 去重 + 双源 + gold set | 失败自动 `quarantine`，人只处理异常 | `equiv.py`✅、M2-8（规划）、M0-2（规划） | 校验人工 ↓90% |

> **关键认知**：L3 不是假设——`gen_pedagogy.py` 已把数学+物理步骤级归因全量 LLM 标注跑通（可续跑补空），证明"AI 预标 + 人校"链路在本环境成立。把它从"标步骤"扩到"标知识点/难度/题型"是同一套路，风险已验证可控。

## 四、产能模型（213 → 3000）

| 路径 | 人时估算（3000 题） | 说明 |
|---|---|---|
| 纯人工录入+标注（15min/题） | **750 人时** | 3000 × 0.25h |
| AI 预标 + 人校（3min/题，L3） | **150 人时** | 标注人工 ↓80% |
| **L3 + L4 变式**（600 底题×3min + 2400 变式×1min） | **≈70 人时** | 产能较纯人工 **×10** |

→ 从 750 人时降到 ~70 人时，**产能约提升 10 倍**，且质量可控（AI 只预标、变式必校验）。

**推荐落地节奏**：先用现有 213 题跑通 T-CAP1（标注自动化）+ T-CAP2（变式）demo → 验证"1 底题→N 变式"产能倍数 → 再并行铺 M5 采集与 T-CAP4 校验管线 → 全程靠 T-CAP5 看板盯覆盖度缺口。

---

## 五、必须守住的红线

1. **版权**：采集源必须白名单 + 法务界定；变式标注"原创改编"来源（T-CAP6）。
2. **标注质量**：LLM 预标必有"人校"闸门，禁止直接入库（T-CAP1 是预标不是免审）。
3. **变式正确性**：必须过 `equiv.py` + 符号验证 + 抽样审计，失败进 `quarantine`（T-CAP2/CAP4）。
4. **分布漂移**：变式易扎堆，需 KP 覆盖度强制配额（T-CAP5）。
5. **与评分闭环隔离**：本方案产能产物默认进 `draft`/练习域；进正式评分闭环仍走 M4 教师确认 + G1/G2 校验，**不触发"完全零人工产题"红线**（见《AI 自动产题可行性方案》）。

---

## 六、一句话结论

提高出题产能 = **AI 预标（T-CAP1，已实证可行）+ 变式复用（T-CAP2，安全倍增）+ 采集/校验自动化（M5/T-CAP4）**，把人的角色从"做"降级为"校"，产能可提升约 10 倍且不踩版权/评分红线。它是 §3.10 M0/M5 与 §3.11 T-PQ 的共同前置使能层，建议与 M0 同期（W10）启动 T-CAP1/CAP2/CAP4。

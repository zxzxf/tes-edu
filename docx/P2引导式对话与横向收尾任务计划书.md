## 一、P2 引导式对话（T-C1 ~ T-C5）

> 目标：把 `/solve` 从"答案输出器"变成"导师"——默认讲解优先，关键节点引导，赶时间可直给。
> 验收总纲（M2 导师上线，分期书原文）：首轮直给率 ≤5%、提示有效推进率 ≥60%、规避放弃率 ≤25%、挫败信号率 ≤15%。

### T-C1 意图识别 + 三档响应路由（1 天）✅ 已完成（2026-10-24）
- **目标**：学生请求自动进三档——求答案→引导档 / 求讲解→讲解优先档 / 赶时间→简版直给档；不再依赖调用方传 `mode`。
- **关键任务与落点**：
  - `agent-backend/app/core/orchestrator.py` `handle_question` 增加意图分类（规则先行：显式关键词"直接答案/赶时间"→直给；问"为什么/怎么做"→讲解；裸问"这题怎么做"默认引导），分类器抽纯函数 `classify_intent(question, context)` 便于单测。
  - 复用 `llm.py` 已有 `mode` 三值，路由结果映射为档位；LLM 分类兜底（一次轻量调用，带缓存，见 T-D1）。
  - 响应体回传 `intent` 与 `mode` 字段，供埋点（T-C4）与 App 展示"当前为引导档/直给档"。
- **验收**：单测覆盖三类意图 + 兜底顺序；`/solve` 不传 mode 时三档分流正确（mock LLM 断言 prompt 中档位标记）；意图误判有显式降级路径（分类失败默认引导档，不静默直给）。
- **实际落地**（提交见仓库）：
  - 新增 `agent-backend/app/core/intent.py`：`classify_intent` 纯函数（规则先行，未命中返回 None）+ `classify_intent_llm` 轻量兜底（temperature=0 / max_tokens=8，任何失败返回 None）+ `resolve_response_mode` 兜底链（规则→LLM→**默认引导档**，不静默直给）。短问句（<12 字）不触发 LLM 分类，最常见形态零成本。
  - `llm.py` 新增 guide 档：_SYSTEM 补引导规则（只给考点+方向+第一步，不给最终答案），_dev_solve 补引导分支；`orchestrator.handle_question` 未传 mode 时走三档路由（显式传值仍尊重，`/similar` 不变）；`schemas` 的 `SolveRequest.mode` 默认改 None、`SolveResponse` 增加 `intent`/`mode`/`intent_source` 回传；`solve.py` 事件上报改记实际生效档位与意图来源。
  - 测试：新增 `tests/test_intent.py` 25 例（三类规则、优先级、兜底链四路径、LLM 解析器、接口级三档分流+显式兼容），agent 套件 72→97 全绿。
  - 线上验证（137，经隧道真实 LLM）：三类问句 intent/mode/source 全部符合预期；引导档真实输出为"点考点+方向+第一步+邀请回应"且未给答案；直给档直接 `x=-3`。
  - **顺带修复生产故障**：agent 容器 `LLM_MODEL=qwen3.8-max`（ws 端点持续 403）导致 `/solve` 全量 500——已改回 `qwen3.8-flash` 并重建容器；`.env.example` 同步更正并加实测口径注释（qwen3.8-max / deepseek-v4.1-flash 持续 403，勿配）。

### T-C2 Hint 阶梯 L0–L4（1.5 天）✅ 已完成（2026-10-24）
- **目标**：实现分期书定义的 Hint 阶梯——**L0 点考点 → L1 给方向 → L2 给关键公式 → L3 给该步推导（不给最终答案）→ L4 完整解析 + 复盘三问**；每轮必须给出可操作信息，禁止空反问。
- **实际交付**：
  - 新增 `agent-backend/app/core/socratic.py`：`decide_level` / `hint_contract_violations` / `template_hint` / `is_frustration_signal` / `is_finale_question` 纯函数 + `HintLadder` 进程内阶梯状态（按 (学生, 题) 隔离，容量淘汰）+ `generate_hint` LLM 生成层。入口为 `/solve` 的 `hint=true`（请求扩 `student_reply` / `direct_reveal`，响应回传 `hint_level` / `hint_level_name` / `hint_frustration_streak` / `hint_finale` / `hint_direct_reveal`）；`orchestrator._handle_hint_round` 编排，`hint_shown` 事件入 Kafka（T-C4 数据源）。
  - 升级策略落地：默认 L0 起；连续 2 次挫败信号跳一级（有实质回应即清零）；压轴题（检索 chunk difficulty=hard）封顶 L3 循环分步；`direct_reveal` 直达 L4 无视封顶。
  - "禁止空反问"契约：`hint_contract_violations` 单点收口（非纯问句 + 含下一步动作 + L1 方向性 + L4 复盘三问），LLM 输出违约/失败一律回落 `template_hint`——契约不依赖 LLM 自觉性；五级模板全部过契约（单测钉住）。
  - **顺带修复（线上实测事故）**：`llm.suggest_similar` / `_remote_solve` 对 LLM 异常零防护，端点配额耗尽（403）时旁路的变式调用能把整轮对话打成 500——两处均已加自治降级（similar 回落检索变式、solve 回落标注"[降级回退]"的通法拼装），回归测试 3 例。
- **验收结果**：`tests/test_hint_ladder.py` 28 例（五级递进/挫败跳级/压轴封顶/直达 L4/契约正反例/五级模板全过契约/LLM 违约与异常回落/状态隔离/接口级四轮对话/降级回归），agent 套件 97→125 全绿；137 经隧道实测四轮：L0 起手 → 连击 1 不跳 → 连击 2 跳 L1 → direct_reveal 直达 L4（复盘三问齐全）；配额耗尽轮次模板兜底全链路不中断。PG 持久化按计划待 T-C4 冒烟后固化。
- **遗留**：RAG 检索质量与阶梯正交（实测"解方程 2x+6=0"检索命中集合题，chunk 知识点串被带入 L0 文案）——归 T-A3/T-F 检索侧治理，不在本项范围。

### T-C3 题型路由 + 分步拆解 + "直接看解析"一等功能（1 天）✅ 已完成（2026-10-24）
- **目标**：按题型分级响应——记忆型直接讲解、中等题引导 1–2 轮、压轴题 3–4 轮 + 分步拆解；"直接看解析"做成一等功能（常驻按钮 + 一次轻确认 + 复盘三问），**行为入埋点且不作为违规**（R6 应对）。

  - **顺带修正 T-C2 线上失效 bug**：`socratic.is_finale_question` 原先只认 `'hard'` 字符串，线上整数难度下**永不命中**（压轴封顶 L3 实际是死的）——已改走 `difficulty_is_hard` 归一化，回归测试钉住。
  - 分步拆解复用 `course_kb_steps`（211 题 668 步全覆盖）：`orchestrator._handle_hint_round` 压轴轮按步骤推进，**先判推进信号再生成本轮 Hint**（学生回应当轮面向下一步）；bundle 经进程内 TTL 缓存（10 分钟 / 256 条）避免每轮两次查询；`HintLadder` 状态增加 `step` 字段（(学生, 题) 隔离）；`template_hint`/`generate_hint`/`_build_hint_messages` 贯通可选 `step` 参数，五级分步模板全部过"禁止空反问"契约（L3 仍不给最终答案）。
  - "直接看解析"一等功能：服务端 `mode=direct` 直达 L4（等价 T-C2 `direct_reveal` 参数，App 常驻按钮走前者）；App 侧（student-app）`SolveRequest/Response` 扩契约字段（question_tier/hint_*/hint_step*），`SolveViewModel` 可注入 + `startHint/replyHint/revealDirect` 三动作，`InputScreen` 常驻按钮 + 一次轻确认 AlertDialog + 阶梯对话区（等级/第 N-M 步/轮次进度）；JVM 单测 `SolveViewModelTest`（fake ApiService，4 例 mock 走通）。

## 二、LLM 成本控制与降级（T-D1 ~ T-D3）

> 目标：市场对比后新增的横向必做项（分期书原文：请求级缓存与去重 + 模型路由 + 降级策略 + 用量监控与预算告警）。当前 `llm.py` 四项全无。

### T-D1 请求级缓存与去重（0.5 天）
- **目标**：同题 / 近似题命中缓存，杜绝重复烧 LLM。
- **关键任务与落点**：
  - 缓存键：`content_hash`（题库已有）+ 学科 + mode + hint_level；近似命中走 `course_kb_embeddings` 向量相似度阈值（≥0.98）去重，复用 T-A3 RAG 通道。
  - 存储：137 `edu-redis`（agent 容器已同网）TTL 7 天；PG 表 `llm_cache` 持久化兜底（防 Redis 清空）。
  - 落点：`agent-backend/app/core/llm.py` `_remote_solve` 入口包一层 `cached_solve`，纯函数 `cache_key(...)` + DB/Redis 薄层（延续既有分层风格）。
- **验收**：单测命中/未命中/近似命中三态 + TTL 过期；重复请求二次不调 LLM（mock 计数断言）；缓存键含 hint_level（同题不同 Hint 级不得混）。

### T-D2 模型路由分级（0.5 天）
- **目标**：简单题/直给走小模型，难题走大模型——按题型 + 难度 + mode 路由。
- **关键任务与落点**：
  - 路由表入 `agent-backend/.env` 可配（`LLM_MODEL_SIMPLE` / `LLM_MODEL_HARD`），默认小模型 `qwen3.8-flash`（端点特性已知：flash 并发最快、滚动配额；deepseek 长 prompt 挂起已实测，不作默认难题模型）。
  - 判定：mode=quick/similar 或题型=单选多选 → 小模型；压轴解答 / mode=explain 且 steps≥3 → 大模型。
  - 与 T-D1 衔接：缓存未命中才进路由。
- **验收**：路由纯函数单测（六类组合 → 期望模型）；`.env` 缺配时回落单一 `LLM_MODEL` 不启动失败；采样 20 请求日志核对模型选择正确率 100%。

### T-D3 降级策略 + 用量监控与预算告警（1 天）

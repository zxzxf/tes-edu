# 学生 Agent 需求变更 任务方案书 v1.5

- 日期：2026-10-29（v1.5：按建议收敛首期 MVP 范围「高三·数学·纯选择题卷」并定案 §6-12/13/14 三项待确认；v1.4：定案组卷权重「知识点覆盖优先 + 教师题优先」、采集卷双路径由教师选；明确 R8 学生端保留讲解/图谱/错题集；v1.3：定案「不建班级、按年级段下发」+「统一题库 + 规则组卷」，附题库实测分布；v1.2：定案统一题库并核实租户缺口；v1.1：修正编号与指标矛盾，补作答输入规范 / 冷启动 / 回滚，新增 §10 已知不足）
- 适用范围：tes-edu（agent-backend / web-backend / gateway / student-app / web-frontend）
- 基线：现有系统为「拍照/输入 → 自由解题 → 判分 → 错题本」的**问答式**形态；本次变更为「教师出卷 → 下发 → 学生作答 → 自动阅卷 → 解析/知识点 → 错题与巩固」的**作业闭环**形态。

## 0. 一句话结论（先看这个）

本次变更的本质是：**把判分判据从"全局题库检索"收敛到"本套试卷自带的答案"**。

这正好切掉了当前判分链路最大的两个误差源——

1. **检索错配**：实测向量相似度 0.9352 也挡不住"差一个从句"（等比题命中带「各项均为正数」的库内另一版本），拿 A 题标答判 B 题，系统性误判；
2. **模型二次重算**：判分时模型独立重算，等于换一个考生（歧义题 `a=1` 判错、切线题点评给出错误答案 `a=5`）。

判据变成"本卷答案"后，**对错是确定性可判的**（等价判定 + 多解展开），LLM 只保留"错在第几步/哪类错"的归因职责。也就是说：**需求 2 不只是业务要求，它本身就是正确率问题的解法**。这一点应作为整套方案的架构前提（见 ADR-A1/A2）。

⚠️ 但有一个必须同时兑现的前提：判分环节变稳之后，**误差会集中到"答案本身"**——一卷答案错，全班被系统性判错，且错得非常稳定。因此 §8 的三道答案质量闸门（G1 双源校验 / G2 新卷抽样复核 / G3 改判触发复查）**与判分改造同等优先级，不可后置**。

✅ 补充硬约束：**试卷题型收敛为三类**——纯选择题卷、纯填空题卷、选择与填空混合卷；**解答题一律只做人工评定，不进自动阅卷**。这是本次对正确率贡献最大的一条：客观题与填空题的答案是**枚举值或短字符串**，等价判定可以完全确定性化，不再需要"理解解题过程"（详见 §2.0 与 §8.5）。

✅ **下发与组卷口径（v1.3 定案）**：**不建班级**，试卷按**年级段（高一 / 高二 / 高三）**下发给学生；题目统一进 `course_kb` 一个题库，由规则组卷器按「年级段 + 学科 + 题型 + 难度分布 + 知识点覆盖」组合题目成卷（§2.6 / M4-2）。⚠️ 实测当前题库 211 行**全部是「高三」的高考真题**，高一/高二题源与教师出题都还没有——这是 M0 的硬前置，不是铺垫。

✅ **组卷权重与采集路径（v1.4 定案）**：组卷时**知识点覆盖优先**（先满足 kp 覆盖度，再凑题量与难度分布），同类题**优先教师出的题**（`teacher > import > crawl > llm_generated`）；采集到的成套卷**整卷入库（P1）与拆题重组（P2）两条都做**，由教师在采集时选择。

✅ **学生端既有功能保留（R8，v1.4）**：讲解、知识图谱、错题集三个模块**全部保留**并接入作业闭环——判错的题自动进错题集，图谱按卷展示本题知识点，讲解在作业场景下同样可查。本次只收敛**自由拍照解题入口**，不替换学生端。

✅ **首期 MVP 范围收敛（v1.5 建议落地）**：题库实测 211 行全为「高三」、教师出题为 0，故首期**只做「高三 · 数学 · 纯选择题卷」**一个最小闭环，跑通后再横向扩年级段/学科/卷型。详见 §9。

## 2. 目标数据模型（新增表，走 `web-backend/migrations/0005_*.sql`）

### 2.0 题型规范（硬约束）

**试卷类型 `paper_type` 只允许三种：**

| 值 | 含义 | 卷内题型白名单 |
|----|------|---------------|
| `pure_choice` | 纯选择题卷 | 全部为 `choice` |
| `pure_blank` | 纯填空题卷 | 全部为 `blank` |
| `mixed` | 选择与填空混合卷 | `choice` + `blank` |

**题目类型 `qtype` 枚举与判分路由：**

| qtype | 说明 | 判分路由 | 是否消耗 LLM |
|-------|------|---------|-------------|
| `choice` | 选择题（`choice_type`: `single`/`multi`） | 确定性判定：选项集合等价 | 否（0 token） |
| `blank` | 填空题（`blank_count` 支持多空，按 `blank_index` 分空判定） | 确定性判定：逐空等价 + 多解展开 | 否（0 token） |
| `subjective` | 解答 / 实验 / 证明等需过程题 | **直落 `manual_pending`，仅人工评定** | 否（**不调用 LLM 判定**） |

**判定规则（确定性，全部可单测）：**

- 单选：选项字母等价（`C` / `c` / `C. 12` 归一化为字母；学生写值而非字母时按"值→选项"回查）。
- 多选：**集合完全相等**才判对；缺选/多选记为 `partial`（是否给分由卷面配置 `partial_score` 决定）。
- 填空：按空位逐一判定，等价集包含分数/小数/根式/±多解/单位/大小写（`61/25` ≡ `2.44`、`±2` ≡ `2` 或 `-2`）；多空默认**全对才得分**，可按空配置。
- 解答题：提交即 `manual_pending`，教师端评定；**不进自动判分准确率的分母**。

> 说明：解答题**允许入卷**（满足"解答题只能人工评定"的要求），入卷时 UI 必须显式标注「本卷含 N 道解答题，需人工评定」，试卷类型仍按"可自动阅卷题"的组合归类。若希望三类卷保持绝对纯净，可改为"解答题不入卷、走独立主观题通道"（见 §6 待确认 10）。

### 2.4 学生作答输入规范（v1.1 新增，决定判定可行性）

**这一节决定了前面所有"确定性判定"是否成立**：如果学生的作答是自由文本或拍照上传，OCR 会把失真重新带回判分链路（`e×`→`e^x` 那类问题），确定性判定就无从谈起。

| 题型 | 输入方式 | 说明 |
|------|---------|------|
| 单选 | 点选选项 | 服务端只收字母，**不做 OCR** |
| 多选 | 多选勾选 | 服务端收字母集合 |
| 填空 | **分空结构化输入**（每空一个输入框 + 常用符号键盘：分数 `/`、根号 `sqrt()`、指数 `^`、±、π） | 服务端按 `blank_index` 收数组，**不做自由文本解析** |
| 解答 | 文本 + 图片上传 | 只人工评定，OCR 失真不影响自动判分 |

红线：**自动判分的题，学生作答必须结构化采集**；任何需要"识别学生写了什么"的环节都不允许进入自动判分路径。

### 2.5 冷启动依赖（v1.1 新增）

M1 的下发与作答依赖"有题可出"，但题库建设（M3-6 录入 / M5 采集）排在后面，直接做 M1 会出现"系统好了但没题"的空转。因此：

- **M0-1（前置）**：教师手动录入题目 + 批量导入（复用现有 `ingest`），先把 `course_kb` 填起来；
- **M0-2（前置）**：题目必须可标注 qtype 与答案，才能被组卷器抽取。

调整后排期：**M0 → M1 → M2 → M4 → M3 → M5**。

### 2.6 统一题库：题目的唯一来源（v1.2 定案）

产品已确认：**教师出的题 + 自动采集的题 + 批量导入的题，全部写进同一张题表 `course_kb`**；试卷只做「引用 + 快照 + 本卷答案」，不为不同来源各建题表。

**现状（2026-10-29 线上实测）：**

| 表 | 角色 | 行数 | 说明 |
|----|------|------|------|
| `course_kb` | **题目主数据（权威）** | 211 | `judge_v2` 查表读 `type / answer / options / stem / analysis`；`course_kb_steps` 以 `content_hash` 关联分步 |
| `course_kb_embeddings` | **检索索引** | 257 | RAG 检索读此表，带回 `content_hash` / `type` / `source_tag` |

二者是**主表 + 索引**关系（`content_hash` 为关联键），不是两张并行题库——这一点实现时容易误解，特在此明确。

**⚠️ 题库现状实测（211 行，决定组卷器能不能出卷）：**

| 维度 | 实测分布 | 对方案的影响 |
|------|---------|------------|
| `grade` | **只有「高三」一个值**（211 全中） | **高一/高二目前无题**，按年级段下发只有高三能出卷 → M0 必须先补高一/高二题目 |
| `subject` | 数学 123、物理 88 | 学科覆盖窄，其他学科组不了卷 |
| `type` | 单选 81、解答 54、多选 40、**填空 21**、实验 15 | 可自动阅卷（单选+多选+填空）= **142 道 / 67%**；解答+实验 69 道只能人工。**纯填空卷仅 21 道可选**，组卷器需能提示"题源不足" |
| `source_tag` | **全部 `gaokao_real`**（高考真题） | 目前**没有一道教师出的题**，教师出题链路（M0-1）是硬前置 |
| `difficulty` | 3→135、4→38、2→23、5→12、**1→3** | 难度严重偏中上，按"易/中/难"比例组卷时**易题不够** |
| `course_kb_embeddings` | **无 `grade` 列** | 按年级筛题只能走 `course_kb`，检索侧暂不支持年级维度过滤 |

> 结论：题库当前只能支撑"高三 + 数学/物理 + 中高难度"的组卷。**M0 的题目供给不是铺垫，是硬前置**——没有它，M4 的组卷器建好也无题可组。

**需要补的字段（并入 `0005` 迁移）：**

```
course_kb 新增：
  tenant_id        -- ⚠️ 现表无此列，是跨租户读取的硬缺口（§6 待确认 13）
  source           -- teacher | crawl | import | llm_generated
  status           -- draft | published | archived（非 published 不可被组卷器抽取）
  answer_values    -- jsonb，多解展开后的判分等价集
  choice_type      -- single | multi
  blank_count      -- 多空填空的空位数
  reviewed_by, reviewed_at
```

**双写约束（写入 M0-1 验收项）**：录题必须同时写 `course_kb` **和** `course_kb_embeddings`（embedding = `qwen3.7-text-embedding`，1024 维，走 ws 端点）。只写主表会导致该题检索不到，教师端能看见但学生端检索/查表命中不了。embedding 生成失败时题目仍可入库，但强制 `status=draft`，由后台任务补向量后再转 `published`。

**对试卷域的影响（§2.1 已同步修订）**：`exam_paper_question.question_id` 由「可空」改为 **NOT NULL**，卷内每题必须来自题库；`stem_snapshot` 保留为快照（题库后续改题不影响已下发卷的判定），`standard_answer` / `answer_values` 是本卷判据（可覆盖库内答案，但须经教师确认，见 G1）。

## 4. 关键设计决策（ADR 摘要）

- **A1 判据唯一化**：判分的**唯一**判据是本卷 `exam_paper_question.answer_values`。禁止判分时重新检索全局题库，更禁止让模型重算题目。理由：重算等于换考生，是过去 4/5 误判事故的共同根因。
- **A2 判分分层**：① 确定性等价判定（0 token）→ ② 题库查表（仅作交叉验证）→ ③ LLM **只做归因** → ④ unknown 转人工。**判定权不在模型手里**。
- **A3 答案隔离**：下发接口**永不返回** `standard_answer` / `answer_values`；解析与答案仅在提交后或教师端可见。B/C 端接口分权（网关 `rbac` vs `jwt_c` 两档已具备）。
- **A4 状态机与幂等**：submission 状态机 `grading → graded/partial_manual`；提交用 client_id 幂等；单题判分失败可重试且不影响他题；人工改判覆盖自动结论并留痕。
- **A5 脏题与合规隔离**：采集/生成内容一律先 `draft`，沿用 `source_tag='quarantine'` 隔离机制。
- **A6 缓存与版本**：判分结果缓存键含 `model@PROMPT_VERSION`（当前 2）；**降级结果不进缓存**；改提示词必须 bump。
- **A7 知识点写侧唯一入口**：所有 `kp_code` 写入继续走 `web-backend/app/services/mastery.py::resolve_kp_codes`，防止 DAG code 体系被写脏。
- **A8 题型白名单与判分路由（R7）**：三类卷 + 解答题只人工；`choice`/`blank` 走确定性判定，`subjective` 不调用 LLM 判定。
- **A9 作答结构化采集（v1.1）**：自动判分的题，学生作答必须按题型结构化提交（点选 / 分空输入），**禁止对自由文本或拍照作答做自动判分**——否则 OCR 失真会把不确定性重新引入判分链路。
- **A10 题库单一来源（v1.2 定案）**：教师出题、自动采集、批量导入一律写 `course_kb`，以 `source` 区分来源、`status` 控制可否被组卷，**不为不同来源分设题表**；试卷只存 `question_id` 引用 + 快照 + 本卷答案。录题须双写 `course_kb_embeddings`，否则检索不到。
- **A11 年级段下发，不建班级（v1.3 定案）**：下发目标是年级段（高一 / 高二 / 高三），**不引入班级实体**。学生身份沿用现有裸 `student_id` 字符串，只补一张轻量级 `student_profile(student_id, tenant_id, grade)` 承载年级归属；**不并入 `sys_user`**（后者是后台管理账号体系，8 行全为 admin/region_admin 类，语义不同）。年级值域与 `course_kb.grade` 对齐。

## 8. 正确率收益拆解：能提高，但有前提（必读）

### 8.1 误差公式

```
最终错误率 ≈ P(答案错)  +  P(判定错 | 答案对)  +  P(不可判定未兜住)
```

| 项 | 现状 | 按本方案改造后 | 说明 |
|----|------|---------------|------|
| P(判定错 \| 答案对) | **高**（检索错配 + 模型重算 + 漏解） | **→ ≈0** | 判定权归确定性代码，0 token、可复现、可单测 |
| P(不可判定未兜住) | 中（unknown 曾回出「判错 + 转人工」的矛盾包） | **→ ≈0** | unknown 直接落 `manual_pending`，不猜 |
| P(答案错) | 高但**分散** | **变成唯一主项，且影响放大** | 判据收敛后，答案错 = 全卷学生被系统性判错 |

**关键结论：本方案把误差从"判分环节"搬到了"答案生产环节"。**
判分环节的错误是**概率性**的（今天对、明天错，冤枉个别学生）；答案环节的错误是**系统性**的（一卷错，全班错，而且错得非常稳定）。所以：

> 只做判分改造而**不做答案质量闸门，正确率不但不升，事故的 blast radius 反而变大**。

### 8.2 三道必须同步做的答案质量闸门

| 闸门 | 机制 | 落地位置 |
|------|------|---------|
| **G1 双源交叉校验** | 有第二来源时（题库标答 / 教师填写 / LLM 独立解）**2 取 2 一致**才允许发布；不一致标红转教师裁决。无第二来源时对**可机械验证**的题型做代入检验（方程/化简/求值），**不可机械验证的题型只能教师人工确认** | M4-6 |
| **G2 新卷抽样复核** | 新卷发布前用"标准学生样本"空跑（正确解 + 常见错法 + 等价写法 + 边界写法），判定分布异常即拦截 | M4-7 |
| **G3 改判触发复查** | 教师改判 / 学生申诉 → 回写标记；同一答案累计 K 次改判即**冻结该题**（停止自动判分、全部转人工）并告警 | M2-10 |

> ⚠️ G1 的边界（v1.1 明确）：**不能用 LLM 自动做"代入检验"来替代教师确认**——那等于又把模型请回来当裁判，与 A2 冲突。LLM 只能给出"待教师确认的建议"。

G3 是让正确率**随时间单调上升**的唯一机制——没有它，错误答案会一直错下去。

### 8.3 正确率指标口径

| 指标 | 口径 | 目标（稳定期 / 首月过渡） |
|------|------|------|
| 判分准确率（分母只含 choice+blank） | `1 − (教师改判题数 / 已自动判题数)` | **≥98% / ≥95%** |
| 人工复核率 | `manual_pending 题数 / 总题数` | 客观填空部分 ≤3% / ≤10%，逐月下降 |
| 判据覆盖率 | `走 paper_answer 判定的题数 / 可自动阅卷题数` | ≥99% / ≥90% |
| 答案可信率 | `G1 校验通过题数 / 新入库答案题数` | ≥98% |
| 冤枉率（最该盯的） | `教师把 correct=false 改判为 true 的题数 / 判错题数` | **→ 0** |
| 解答题人工评定时效 | 提交 → 评定完成 P50 / P90 | 由业务定 SLA |

监控维度：按卷、按教师、按知识点下钻；新卷首周强制 100% 抽样复核。

### 8.4 诚实结论

- **闸门 + 指标门禁同步落地**：判分错误率可望从当前"高频"降到 **≤2%（稳定期）**，"冤枉学生"这一类接近归零——这是本次改造最大收益。
- **只做判分改造不做闸门**：判分环节确实变稳，但某卷答案一错就是全班系统性判错，**比现状更糟**。
- **解答题**不要指望自动判分，已转人工，这是正确取舍。
- 上述判断基于**两天 5 道题的样本与线上 569 次调用统计**，是方向性结论而非统计显著结论；真正的准确率要用 M2-8 的 gold set 跑出来才算数。

### 8.5 题型收敛（R7）带来的额外收益

| 维度 | 不收敛（含解答题自动判） | 收敛后（三类卷 + 解答题人工） |
|------|------------------------|---------------------------|
| 判定可否确定性化 | 否（需理解过程） | **是**（枚举值 / 短字符串等价判定） |
| 判分是否消耗 LLM | 是（每题一次，还会重算） | **0 token** |
| 判分延迟 | 每题 1–4s | **毫秒级** |
| 准确率上限 | 受模型天花板约束 | **受等价判定实现质量约束 → 可单测、可逼近 100%** |
| 出错形态 | 概率性、难复现 | 可复现、可定位、可回归 |
| 人工成本 | 隐性（没人盯） | 显式（解答题人工 + 工单队列） |

准确率目标定为 98% 而非 100%：剩下的 2% 不再是"模型发挥不好"，而是"等价写法没覆盖到"——**每暴露一个就能补一个单测永久修掉**，是可收敛的。

## 10. 已知不足（v1.1 新增，自检）

方案书的判断里，以下几点**尚未被证实或尚未覆盖**，开工前应补：

1. **准确率结论的样本量不足**：5 道题 + 569 次调用统计只够支撑"方向对"，不够支撑"98% 能达成"。真实数字必须由 gold set 跑出来。
2. **G1 的"双源"在冷启动阶段拿不到第二来源**：新录入的题只有教师填的一个答案，双源校验会长期空转。冷启动期应以"教师确认 + 抽样复核"为主，双源校验作为题库成熟后的增强。
3. **成本模型未估**：解析生成（每题一次 LLM）、定时采集、组卷都属于批量调用，token 成本与配额上限没有测算；ws workspace 预算此前已出现过 429 耗尽。
4. **多租户隔离只写了原则，且已定位到具体缺口**：`course_kb` 现有 211 行**没有 `tenant_id` 列**，旧数据的归属规则未定（§6-13）；试卷/采集/知识点也都要按租户隔离，但落到哪些接口、如何防跨租户读取，仍只有一句话，实现前需列接口清单。
5. **学生端离线与并发未细化**：多设备同时作答同一份卷、草稿冲突合并，只写了"client_id 幂等"原则，未定义冲突策略。
6. **未定义答卷留痕与申诉**：学生申诉入口、改判审计日志的保留期限与查询方式未设计。
7. **采集的法律边界只写了"合规校验"**：具体规则（是否允许采集公开题库、教辅扫描件）需要业务给清单，否则 M5 无法验收。
8. **题源缺口的补充途径未规划**：方案只写了"教师手动录题 + 批量导入"，但实测高一/高二 0 题、填空题仅 21 道、难度 1 仅 3 道、教师出的题 0 道。靠手动录题补到"可组卷"的规模是**运营工程**，需要单独的题源采购/采集计划与预算（与 §7「不含内容运营」是同一件事）。

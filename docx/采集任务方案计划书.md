## 1. 背景与目标

### 1.1 业务诉求
教研/教师需要把外部课程素材（教材、大纲、题库包、网页、视频）**自动采集进来**，并拆解出结构化知识点体系挂载到图谱，最终进入统一题库 `course_kb` 与知识点 DAG（`kp_node`），供组卷、讲解、图谱复用。

### 1.2 痛点（历史）
早期 `run_job` 只接收调用方显式传入的 `items`，**从不读 `CourseSource.uri`**，导致 `POST /jobs/{id}/run` 与定时调度都只会写一条 `fetched=0 / inserted=0` 的空运行记录——"采集任务"形同虚设。v5.9 已通过 `crawl_fetch.py`（A 形态重构后为 `app/crawl_service/fetcher.py`）补齐"从源抓取+解析+入库"的真实链路。

### 1.3 目标闭环
```
建课程源(course_source) → 建采集任务(crawl_job) → 执行一次/定时
   → 抓取源内容(fetch_source_content) → 解析成题目(parse_items)
   → intake 去重入库 draft(course_kb + embeddings / exam_paper_intake)
   → 知识点拆分挂载(kp_node, draft) → 教师审核发布 → 学生端可见
```

## 3. 数据模型

### 3.1 采集域（R6 / R4）
```
course_source        课程源（教材/大纲/视频/网页/题库包）
  id, tenant_id, name, source_type, uri, parser, status, ingested_at

crawl_job            定时采集任务
  id, tenant_id, kind(paper|question|course), schedule(cron),
  params(jsonb), enabled, last_run_at, last_status, budget_limit

crawl_run            单次运行记录（M5-6 可观测）
  id, job_id, tenant_id, status(running|ok|failed|stopped),
  fetched, inserted, duplicated, failed, budget_stop,
  paper_id, error, started_at, finished_at

exam_paper_intake    采集卷入库中间态（P1 整卷 / P2 拆题）
  （承接 M4-4 双路径：P1 整卷落 exam_paper + 题目逐条进 course_kb；
   P2 先入库再重组）

kp_node              知识点（纳入课程维度与来源追溯）
  code(PK, 沿用 MA-B4-C1-S2-K02), course_id, parent_code, name,
  source(manual|crawled), status(draft|published), created_at

question_kp          题↔知识点绑定（覆盖度与置信度）
  question_id, kp_code, weight, source, confidence, reviewed_by
```

### 3.2 关联约束
- 所有采集写入**强制 `tenant_id` 过滤**（单写者原则：仅 `web-backend` 写 `course_kb`，`agent-backend` 只读）。
- 采集/生成内容一律先 `draft`，沿用 `source_tag='quarantine'` 隔离（ADR A5）。
- 入库必须**双写 `course_kb` + `course_kb_embeddings`**（embedding = `qwen3.7-text-embedding` 1024 维，走 ws 端点）；向量失败仍入库但强制 `draft`。

## 5. 端到端链路设计

### 5.1 建源
- `POST /sources` 建 `course_source`（指定 `source_type` + `uri` + `parser`）。
- `POST /sources/{id}/status` 启停；`DELETE /sources/{id}` 删除（级联止任务）。

### 5.2 建任务
- `POST /jobs` 建 `crawl_job`（`kind` / `schedule` cron / `params` / `budget_limit` / `enabled`）。
- `POST /jobs/{id}/status` 启停；`DELETE /jobs/{id}` 删除（避免孤儿任务）。

### 5.3 执行一次（真实抓取）
1. `POST /jobs/{id}/run` → `run_job(db, job)`。
2. `items is None` 时调 `_resolve_items_from_source(db, job)`：
   - `url` → `safe_fetch_url`（SSRF 闸门：仅 http/https，host 禁本地/私网/云元数据 `169.254.169.254`，且解析出的每个 IP 也必须公网，防 DNS 重绑定）。
   - `web` + http(s) URL → **同样走 `safe_fetch_url`**（v1.1 修复：此前误归本地文件读取）；`web` + 本地路径仍走 `read_local_file` 兼容存量。
   - **抓取加固（v1.2，`dc1c9d4`）**：`safe_fetch_url` 带浏览器 `User-Agent` / `Accept` 头（修复 w3schools 对 httpx 默认 UA 返回 403），并关闭自动重定向、改为手动逐跳（上限 5）且**每跳重过 `_resolve_safe`**，防止站点 302 到 `169.254.169.254` 绕过首跳闸门。
   - `file` / `bank_pack` / `bank` → `read_local_file`（限 `COURSE_SOURCE_ROOT=/opt/course-sources`，防目录穿越）。
3. `parse_items(content, source_type)`（同步纯函数）：
   - `bank`/`bank_pack`：JSON 数组 → 中文字段映射成英文字段 → `normalize_item` 入参。
   - 其他：先试 JSON；失败打 `NEEDS_LLM` 标记返回，**不再静默 0 条**。
4. **M5-2 LLM 抽取（v1.1 新增）**：`needs_llm(reason)` 为真时，编排层转交
   `crawl_service/llm_extract.py` → 清洗 HTML（`max_chars` 截断）→ 组装提示词 →
   模型通道（租户 BYOM 优先，全局 env 兜底，base_url 过 SSRF 闸门）→ 稳健解析
   JSON → schema 校验（复用 `map_bank_record` + `normalize_item` 口径，丢弃无题干/答案的题）
   → items。任何失败返回可读原因写进 `run.error`，模型调用类故障记 `failed`。
5. `intake(db, job, items, run_id)`：按 `content_hash` 去重，入库 `draft`；预算按"本次可入库条数"截断后再建卷，避免"卷已建、题只进一半"的破卷。
6. 写 `CrawlRun`（fetched/inserted/duplicated/failed/paper_id/error/budget_stop）。

### 5.4 审核与发布
- `POST /kp-nodes` 挂载知识点（默认 `draft`）；`POST /kp-nodes/{code}/review` 审核发布。
- `POST /runs/{id}/rollback` 一键回退本次采集。

### 5.5 可观测
- `GET /metrics`：成功率、去重率、失败原因分布、最近 200 条运行（可重试）。
- `POST /jobs/{id}/retry`：从 `stopped` 恢复并立即跑一次；预算用尽时拒绝重试并写明原因。

## 7. 关键设计决策（ADR 摘要，复用项目既有决策）

- **A5 脏题与合规隔离**：采集/生成内容一律先 `draft`，沿用 `source_tag='quarantine'` 隔离机制，未审核不进组卷器/学生端。
- **租户隔离**：所有读写接口按 `user.tenant_id` 过滤；`course_kb` 存量真题统一归 `school_pilot_01`（B 端演示/联调账号 `pilot@school01.edu`）。
- **SSRF 安全抓取**：`url` 源仅放行公网 http/https，host 与解析 IP 双重复查，防本地/私网/云元数据与 DNS 重绑定。
- **目录穿越防护**：`file`/`bank_pack` 只允许读取 `COURSE_SOURCE_ROOT` 内文件。
- **预算停止**：超 `budget_limit` 立即停并打 `budget_stop`；重试时若预算用尽则拒绝，避免"假修复"错觉。
- **去重幂等**：以 `content_hash` 去重；同一源重复采集不重复入库（`duplicated` 计数）。
- **知识写侧唯一入口**（A7）：`kp_node`/`question_kp` 仅经审核/挂载接口写入，采集与手动录入共用同一入口，避免多写者冲突。

## 1. 目标与范围

**目标**：用一个小程序（个人主体、免费、不认证）作为 **PC/Web 站点的扫码登录跳板**——网站弹小程序码，用户微信扫 → 自动进入小程序确认页 → 后端换 openid → 网站自动登录。

**范围边界**：
- ✅ 只做「扫码登录跳板」，小程序内**不做任何业务**（无题库、无练习、无支付）。
- ✅ 服务于现有 `web-frontend`（管理后台）、`student-web`（学生网页端）的登录入口增强。
- ❌ 不包含微信官方「网站应用扫码登录」（那套需企业资质 + ¥300 认证，个人不可行）。
- ❌ 不获取手机号 / unionid（这些需微信认证，个人主体无）。

**价值**：个人主体 0 元、0 营业执照，绕开微信官方扫码登录的企业门槛，给 Web 端带来「免输账号密码」的登录体验。

---

## 2. 两种「扫码登录」对比（决定为什么走自建跳板）

| 维度 | 微信官方「网站应用扫码登录」 | 自建「小程序扫码登录跳板」 |
|---|---|---|
| 主体要求 | **企业** + 微信认证 | **个人实名**即可 |
| 费用 | ¥300（一次性认证） | **0 元** |
| 用户体验 | 扫码 → 微信内弹授权 → 直接登录（最丝滑） | 扫码 → 进小程序确认页（loading 1 秒）→ 网站登录 |
| 能拿到的身份 | openid + unionid（认证后） | **仅 openid** |
| 能拿手机号 | 认证后可（`getPhoneNumber`） | ❌ 不可 |
| 实现复杂度 | 微信托管，配置回调域名 | 自建 ticket + 小程序码 + 轮询（中等） |
| 个人可行性 | ❌ 不行 | ✅ 可行 |

> 结论：对个人主体，唯一可行的是**自建小程序扫码登录跳板**。

## 3. 技术架构与时序

### 3.1 整体链路（5 步）

```
[Web 前端]               [web-backend]                 [微信 API]              [小程序确认页]
    |                         |                              |                      |
(1) 请求登录二维码  ───────▶ │ 生成 ticket(32hex)            |                      |
    │                        │ 存 DB(ticket, pending, TTL)   |                      |
    │                        │ 调 getwxacodeunlimit ───────▶ │ 返回小程序码(图片)    |
    │  ◀─────────────────────│ 返回 {ticket, qrcode}         |                      |
    │  展示二维码 + 轮询      │                              |                      |
    │                        │                              |                      |
(2) 用户微信扫小程序码 ──────────────────────────────────────────────────────────▶ 打开确认页(onLoad 取 scene=ticket)
    │                        │                              |                      │ wx.login() → code
    │                        │  (3) POST /scan/login/confirm(ticket, code) ◀───────│
    │                        │ 调 code2session ───────────▶ │ 换 openid            |
    │                        │ 查/建用户 → create_token ──▶ 签发 JWT                |
    │                        │ 更新 ticket=confirmed+token  |                      |
    │  (4) 轮询 /scan/login/status(ticket) ─▶ 返回 confirmed + JWT                  |
    │  (5) 拿到 JWT → 登录态生效，关弹窗                                                      │
```

### 3.2 接口清单（全部走 web-backend，网关不鉴权）

| 方法 | 路径 | 说明 | 调用方 |
|---|---|---|---|
| POST | `/scan/login/create` | 生成 ticket + 小程序码（base64 PNG），存 `pending` | Web 前端 |
| GET | `/scan/login/status?ticket=` | 轮询：返回 `pending` / `confirmed`(+JWT) / `expired` | Web 前端（每 1.5s） |
| POST | `/scan/login/confirm` | 收 `ticket` + `code`，`code2session` 换 openid → 建/取用户 → 签 JWT → 标记 `confirmed` | 小程序确认页 |

> 这三个接口与现有 `/login`（占位账号密码）平行，都是「拿 token 的入口」，网关 `mode: ""` 不鉴权。

## 4. 改动清单

### 4.1 后端 `web-backend`（FastAPI + SQLAlchemy async + RS256 JWT）

| 文件 | 改动 | 说明 |
|---|---|---|
| `app/core/config.py` | 新增 `mp_app_id` / `mp_app_secret` | 微信小程序 AppID/Secret，**仅环境变量注入**，不进 git |
| `app/models/scan_login.py`（新） | `ScanLoginTicket` 表 | `ticket`(PK, 32hex) / `openid`(nullable) / `jwt_token`(nullable) / `status`(pending|confirmed|expired) / `expire_at`(datetime) |
| `app/models/wx_token.py`（新） | `WxAccessTokenCache` 表 | `access_token` / `expires_at`；缓存微信 `access_token`（2h TTL），多副本共享 |
| `app/services/wechat_mp.py`（新） | `get_access_token()`（带缓存） + `get_unlimited_qrcode(scene)` + `code2session(code)` | 微信服务端调用封装 |
| `app/api/scan_login.py`（新） | 上述 3 个接口；`create`/`status` 不需登录，`confirm` 不需登录 | 复用 `create_token(user_id, role, tenant_id=None)` 签 C 端 JWT |
| `main.py` | `app.include_router(scan_login.router, prefix="/scan")` | 挂载路由（无鉴权前缀，鉴权由网关 `mode:""` 处理） |

**用户身份映射策略（个人主体仅 openid）**：
- 首次扫码：`openid` 在 `sys_user` 无匹配 → 新建一个 C 端用户（`role=student`，`tenant_id=None`），记录 `openid`。
- 二次扫码：命中同一 `openid` → 直接登录。
- **与现有账号合并**：提供「绑定已有账号」接口（用户输入原账号密码 → 把 `openid` 绑到该 `sys_user`），解决 openid 无法跨端统一的问题。本期仅做基础映射，绑定为可选增强。

## 7. 关键限制与风险

| 限制 | 影响 | 应对 |
|---|---|---|
| 个人主体**仅能拿 openid** | 无法跨端统一身份、无手机号 | openid 作唯一身份 + 提供「绑定已有账号」可选增强 |
| `scene` 参数最长 32 字符 | 不能塞 JWT/URL | 只放 ticket（32hex 刚好），其余走后端查 |
| 小程序码指向**正式版** | 真机扫码前需至少上体验版/正式版 | 开发阶段 `check_path:false` + 开发者工具模拟；联调前发布体验版 |
| 小程序仍需「工具」类目发布 | 个人可过，但需类目 | 类目选「工具 > 信息查询」（已确认个人可行） |
| `access_token` 2h 过期 | 每次出码现取会超限频 | 用 `WxAccessTokenCache` 表缓存，多副本共享 |
| 微信 `code2session` 频率限制 | 高并发扫码可能触发 | 出码/确认接口加限流（网关已配 rate），ticket 幂等 |
| openid 与现有账号不自动合并 | 老用户扫码会建新号 | 提供绑定接口（可选增强，非本期必须） |

## 8. 与现有登录体系的关系

- 现有 `web-backend` 登录：`POST /login`（占位账号密码）→ `create_token(user_id, role, tenant_id)`。
- 新增扫码登录：`/scan/login/*` → 同一套 `create_token` 签发，**令牌格式完全一致**，网关 `jwt_c` 验签通用。
- 两条登录入口并存：账号密码（已有）+ 扫码（新增）。管理后台/学生端登录页可同时展示两个入口。
- 身份合并：openid 首次建号 → 用户若想并入原账号，走「绑定」接口（输入原账号密码校验后关联 openid）。

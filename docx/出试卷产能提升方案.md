# 出试卷产能提升方案（T-PCAP 系列）

> **编写日期**：2026-10-29
> **目的**：在现有《总任务清单与排期计划》之外，单列"**如何提高出试卷（组卷）效率与产能**"专项方案——把"出一份卷"从教师手工拼题，升级为"填参数 / 一键 / 批量"产出，并让 **M4（教师出卷）、T-PQ（学生自适应）、预测试卷** 三者共用同一组卷内核，禁止三套各写。
> **与《出题产能提升方案》(T-CAP) 的分工**：T-CAP 解决"**造题供给**"（213→3000 题，AI 预标+变式）；本方案解决"**把题拼成卷的吞吐**"。两者是**消耗端 vs 供给端**的配对——`course_kb` 越厚，出卷组合空间越大、撞车越少，故 T-PCAP 的硬前置是 T-CAP。
> **已落地积木（直接复用）**：`compose.py`（按知识点抽题/变式推荐✅，T-A4 真实可用）、`equiv.py`（等价判定✅）、`kb_kp_prerequisites`（435 边、无环✅）、`judge_v2`（判分✅）。

---

## 一、出试卷 vs 出题（先厘清概念）

| 维度 | 出题（T-CAP，供给） | 出试卷（本方案，吞吐） |
|---|---|---|
| 产出 | 单道题（进 `course_kb`） | 一套卷（exam_paper + 题序 + 答案 + 分值） |
| 瓶颈 | 录入+标注+校验人工 | 拼题规则+重复开发+人工逐卷审 |
| 使能对象 | M0/M5 题库、T-PQ 候选集 | M4 教师出卷、T-PQ 自适应、预测试卷 |

→ 本方案**不重复造题**，只提升"从已有题库快速、批量、低错地产出合规试卷"的能力。

## 四、产能模型（出一份卷）

| 路径 | 耗时（单卷） | 说明 |
|---|---|---|
| 教师手工拼题（现状占位） | ~30 min | 逐题挑、排、配答案 |
| 参数化模板填参（P2） | ~2 min | 固化默认集，填参数即出 |
| **批量一键（P2+P3）** | ~2 min + 1 min/套 | 一次出 A/B/N 套平行卷 |

→ 单卷操作成本 ↓90%+，且一次产出多套合规卷，**吞吐约 ×15（按 N=10 计）**。

**推荐节奏**：先 W13 与 M4-2 同步做 T-PCAP1（内核统一，去重立项）→ 接 P2 模板 + P4 LLM 草稿 → W14 接 P5 自动闸门。全程依赖 T-CAP 把 bank 扩厚，否则组合空间受限。

## 五、必须守住的红线

1. **不凭空产题**：卷中每题必须来自 `course_kb`（已审核/已校验），LLM 只做"草稿排布 + 引导语"，不在卷中造新题（与"完全零人工产题"红线一致）。
2. **答案隔离不下发**：卷面答案不向学生暴露，判分用本卷自带答案。
3. **G1/G2 校验**：有第二来源才发布，否则转教师裁决；新卷抽样空跑异常即拦截。
4. **进评分闭环仍教师确认**：自动产出的卷一律 `draft`，正式下发前教师确认（M4-6）。
5. **硬前置**：出卷产能受 T-CAP（题库产能）约束——bank 213→3000 未达标前，"组合整卷"组合空间有限，优先跑"单元级/纯选择"MVP。

## 六、一句话结论

提高出试卷产能 = **组卷内核统一去重（T-PCAP1，省 2 套开发）+ 参数化模板（T-PCAP2）+ 批量平行卷（T-PCAP3）+ LLM 草稿批量（T-PCAP4）+ 自动质量闸门（T-PCAP5）**，把"出卷"从手工拼题变成填参/一键/批量，吞吐约 ×15。它是 §3.10 M4 与 §3.11 T-PQ 的共用使能层，🔴 硬前置是 §3.12 T-CAP 的题库产能。
